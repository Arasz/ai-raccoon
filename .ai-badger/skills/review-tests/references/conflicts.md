# Conflicts — final rulings (C1–C21)

L3a's C1–C12 restated as one-line rulings, plus nine found across lanes (C13–C21). `T0-*`
principles are cited here, not in a finding — this file is where they earn their keep.

| # | Conflict | Ruling |
|---|---|---|
| C1 | "Integration tests are the highest-value tests" vs the pyramid | Both, on different axes: value per *test* peaks at integration, value per *second* and diagnosis quality at unit — write the integration test first to pin the wiring, then push branch coverage down (`T1-CST-02`). |
| C2 | Mock verifications count as assertions vs the mock earns none | Split by direction: an **outbound** interaction that is itself the observable contract may be asserted on the double; an inbound/incidental call is asserted as state (`T1-DBL-04`). For `T1-ORC-01` a verify still counts — shallow, not empty. |
| C3 | DRY vs DAMP in tests | DAMP inside the body, DRY for the machinery (`T1-STR-01`). |
| C4 | "Sleeps are fine in integration tests" vs never sleep | Never sleep (`T1-ISO-02`); the local evidence is one-directional — every fixed delay in this codebase's history was a latent flake or a mask. One carve-out: a documented third-party rate limit, paired with a condition check. |
| C5 | In-memory fakes are a Mystery-Guest remedy vs fakes are where the false green lives | Both, once the fake is **bound** — the permission is conditional on `T1-DBL-01`. An unbound fake is a finding regardless of how clean the test reads. |
| C6 | One assertion per test vs assert a secondary observable | One *concept*, as many assertion calls as it needs, each distinguishable on failure (`T2-UNIT-05`). Assertion Roulette is a diagnosability defect, never a reason to delete a real check. |
| C7 | Snapshots are structural assertions vs snapshots are change detectors | A snapshot is a *low-specificity* assertion: it satisfies `T1-ORC-01` and fails `T1-SCO-01` alone, so it is paired with explicit business assertions and never counted as coverage of a rule or calculation. |
| C8 | ">80% mutation score in CI" vs scoped, on-demand, never in CI | Follow the local ruling: mutation is an *investigation* tool with hand-verified survivors; gate on `T1-PRF-01` instead — the same guarantee without a denominator that excludes the non-compiling share and mis-reports `static readonly` survivors. |
| C9 | MS EF docs' `repositoryMock.Verify(...)` vs "don't test implementation details" | The repository is a port you own, so the double is permitted — but the assertion belongs on the controller's output, and the repository implementation still needs a contract against the real engine (`T1-DBL-01`), or the pattern has merely relocated the untested code. |
| C10 | TDD's "delete code written before the test" vs adding tests to existing code | The iron law governs *new* work; for existing untested code write a characterization test, named as such, then red-proof before changing anything. |
| C11 | "Ignored test" is low-severity clutter vs dormant bindings are broken code | Low while it sleeps, **major at the moment of un-ignoring** (`T1-STR-03`). |
| C12 | Beck's desiderata conflict with each other by design | Not a checklist to satisfy simultaneously: name which property each tier optimises — the small lane buys Fast/Isolated/Specific and gives up Predictive; the integration lane buys Predictive and pays in all three (`T1-CST-01` makes the trade explicit). |
| C13 | A rule vs the reference implementation's measured practice (L3b: test ids outnumber source attributes 263:136, and the house style *is* test-id-first) | The rule stands; the measured practice is the **finding**, not a counter-example. A project's current shape is evidence for an L4 exception with a written reason (`governance.md` §L4) — never a silent amendment to a shipped rule. |
| C14 | L3a `K-SNP-01` (a serialized API response is a legitimate snapshot) vs L3b `F-SNAP-01` (no DOM snapshot, ever) | Not a conflict once split by artifact: **stable, non-visual, serialised** artifacts (a generated file, a wire body, an error map) yes; a component tree never — a snapshot diff cannot say which change was the defect, so the reviewer accepts all of them. |
| C15 | L2 `T7` (tolerance-based time assertions, `closeTo`) vs `T1-ORC-03` (tightest predicate) and `T1-ISO-01` (no wall-clock) | Truncate consistently on both sides. A tolerance is admissible only over a **fake** clock's quantum, never over real elapsed time — a `closeTo` on a real duration is `T1-ISO-01` wearing a matcher. |
| C16 | L2 `T8` (auto-advancing fake clock, condition-based flushing) vs `T9` (advance explicitly and deliberately) | Explicit advance for business logic and timers, where the intent must stay legible; auto-advance only for UI settle where the assertion is condition-based — and never both in one test (`T6`). |
| C17 | L2 `P3`/`P5` (define thresholds and wire them into the normal test framework so they gate CI) vs `T1-ISO-01` (no wall-clock assertion; perf in its own lane) | **Both, once the lane is named.** A percentile/error-rate threshold is a legitimate assertion *inside the performance lane*, on controlled hardware, excluded from the default gate. The rule forbids a budget in the default suite, not the existence of budgets — the failure mode is a p95 assertion in a unit lane, which is an environment sampler. This is the sharpest cross-lane conflict and the one most likely to be mis-resolved as "no perf assertions anywhere". |
| C18 | L2 `U16` (quarantine flaky tests) vs `F-E2E-06` (retries ≤1–2; a spec that only passes on retry is a defect) | Retry is a **diagnostic** (trace on first retry); quarantine is the **disposition**, with an expiry. Retries may never substitute for quarantine, and a permanently-retried spec is an unfiled defect (`T1-ISO-08`). |
| C19 | `dotnet-test:grade-tests`' A–F letter grades vs ai-badger's explicit refusal to carry them | No letter grades. A band invites arguing about the band instead of fixing the finding; severity + finding only. The sub-dimension *weights* are still useful as a review-ordering hint and may be cited as such. |
| C20 | FIRST's "Fast" vs `T1-CST-05` (the runner must be able to observe the property) | Speed never buys a blind runner (`T0-08`). Where the cheap runner cannot see the property, the test moves up and the cost is accepted; "it's slow" is not a reason to assert geometry in a DOM shim. |
| C21 | `dotnet-test:code-testing-agent`'s flat "aim for 80% coverage" vs `T0-02` and the measured coverage hole (`evidence.md` test-suite-shape) | No coverage threshold anywhere in the ruleset. 76.1% overall concealed auth middleware at 0% over the 19 lines every one of 106 endpoints depends on. Rank by risk (CRAP: complexity² × uncovered³) and gate on a proven red, not on a percentage. |
