# Minimal comments

Write a doc comment as the 1-3 line contract an editor shows on hover — what the thing is and how
to use it — and never let a PR, issue or ticket reference appear anywhere in it. Cite a spec or
decision record only in the format's own references section (`<seealso>`, `@see`), never in the
description itself. Inline comments say only what the code cannot; tests get one sentence or none.
