# Record the decision before you build it

Every change that adds a feature or meaningfully changes how something works gets a decision record before implementation starts, written with the `decision-record` skill in the format this project already keeps: its ADR log, its spec framework, or both as a linked pair. A bug fix that restores intended behaviour, a refactor with no behaviour change, and docs need no record. A reversed decision gets a new record that supersedes the old one, never an edit to the old one.
