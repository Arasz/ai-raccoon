# Let git write git's own storage

Write a git dir through `git config`, `git remote` and `git branch --set-upstream-to`, each of which takes the config lock and rewrites only the key it was given. A text editor, a shell redirect or a `sed -i` rewrites the whole file instead, so one mistake discards every section it did not reproduce — a rewrite that trimmed a `.git/config` to 296 bytes dropped `remote.origin.fetch` and nearly every `[branch]` section, and the loss stayed silent: `git fetch origin` still reports success and exits 0 while `refs/remotes/origin/*` quietly stops moving, freezing `origin/main` at the commit it held when the file broke, so every later diff, log, merge-base and rebase target answers about a snapshot instead of the remote. `git config --edit` is not the safe alternative — it opens that identical raw file in your editor, and the git-internals guard refuses it the same as a manual edit. Nothing under a git dir is a text file you edit; it is a database git owns.
