# Implementation plan — attach-or-start + cryptographic proof of backend identity

Task `air-backend-launch-identity-proof` · ruling of 2026-09-22 (message bus) + p34 fold-in (F49, F39).

## 0. Evidence conventions (apply to every gate)

- **RED-A** — a behavioral gate that fails at *today's* code (pre-fix). Its red must be watched with `dotnet test --project tests/AiRaccoon.Tests --filter-class '*<Class>'` (never `--nologo`) and the failure output recorded in the package PR before any fix lands.
- **RED-B** — a gate against a contract that does not exist today (build failure is the honest red at today's code, recorded as such). Each RED-B gate additionally names a **mutation** that must be watched red after the code lands and then reverted with no trace (the ADR-0105 "Evidence" convention, `docs/adr/0105-...md` "Evidence" section).
- **Positive control** — a sibling gate proving the fixture can produce the *success* shape, so a hostile gate cannot pass because the fixture is broken ("a check you have not seen fail is a defect" — `.ai-badger/invariants/prove-the-check-fails.md`).
- Fixture realism: no degenerate fixtures (multi-command sequences, >1 element, real key material, non-empty roots where a bank is in scope); every hostile gate asserts a **behavior radius** (e.g. bounded elapsed time, zero secret bytes *and* zero non-proof requests, files-on-disk state), not just a return value.

## (a) Design decisions — one recommendation per known unknown

**D1 — Key shape: ECDSA P-256 asymmetric keypair (PKCS#8 PEM), via `System.Security.Cryptography.ECDsa`.**
Rationale: the owner's "generate a private key … only ai-raccoon will have this key" is possession-proof by signature — the verifier side never holds proving material, so even a compromised CLI/proxy process cannot impersonate a backend.
Rejected: symmetric HMAC-SHA256 (every verifier would hold the very secret it checks against, contradicting "only ai-raccoon will have this key", and it tempts D6's derive-the-token rewrite); Ed25519 via libsodium/NSec (not in the BCL — adding a crypto dependency violates `.ai-badger/invariants/no-hand-rolled-crypto.md`'s platform-API rule).

**D2 — Key scope/location: one keypair per data root, stored in the bank state directory `BankDirectoryFor(options)` alongside `memory.db` (F49-constrained).**
Rationale: per-root keys make cross-root relay fail *cryptographically* (the relay fixture, T16/T28/T40) and the key survives backup/restore with the bank it identifies (F49's measured "backups of `.ai-raccoon/` silently omit the credential", `REVIEW-ASSEMBLED.md:452-462`). "Bank state directory" = the directory holding the bank: `<dataRoot>/.ai-raccoon/` for project scope, `<dataRoot>` for user scope (`SqliteConnectionFactory.cs:165-176`) — the measured harm (unignored secret in a repo working tree) is the project-scope split, and the fix puts the secret where the bank and the log already are.
Rejected: per-installation/user key (one leaked file then impersonates every root on the machine and cross-root relay produces a *valid* proof); per-process ephemeral keys (a second client attaching to a server started by another process could never verify it — attach-or-start dies).

**D3 — Proof wire: `POST /identity-proof`, a custom non-MCP endpoint on the backend's existing loopback listener (ruling clause 3 explicitly allows it).**
Request: `{"v":1,"nonce":"<base64url 32 verifier-random bytes>","audience":"<host:port being challenged>"}`. Response: `{"v":1,"keyId":"<base64url SHA-256(SPKI DER)>","sig":"<base64url ECDSA-SHA256 over the transcript>"}`. Transcript = `ai-raccoon/identity-proof:v1\n` + `keyId` + `\n` + `audience` + `\n` + `nonce` (domain-separated, all four fields bound). Verifier pins the keyId to its own data root's key, so a signature from any other key fails. The listener signs **only when the challenge audience equals its own bound socket** (checked from `context.Connection.LocalPort`), which kills cross-port relay even before key pinning. Replay window = one attempt: the nonce is fresh per challenge (`RandomNumberGenerator`), never reused. Verifier hardening: strict JSON parse, 8 KB response bound, 2 s proof budget, fail closed on anything unexpected. The endpoint joins `McpTokenGate.OpenPaths` (`McpTokenGate.cs:33`) as a *deliberate, commented* exception: it exists to authenticate the server to the client, precedes any secret, and signs only the fixed transcript shape (a bounded signing oracle over verifier nonces — accepted and recorded in the ADR revision).
Rejected: proof over the `/mcp` handshake (the token has already crossed by then — ADR-0105's own rejection ground); `/observability` name check (self-asserted, `ServerRestart.cs:110-124` shows it is only a claim); unix-socket proof channel (a transport redesign ADR-0105 explicitly deferred, `docs/adr/0105-...md` "Private channel and TOCTOU" — the ruling did not reopen it); timestamped self-signed beacon with no verifier nonce (replayable — the captured-response fixture T15 would pass).

**D4 — Failure mode on a squatted port: fall back to a private ephemeral backend (F70's machinery demoted to fallback) + a loud warning naming the squatted port and the remedy; fallback backends carry `--idle-timeout 00:05:00` and are stopped by the spawner when it has a lifetime hook (the proxy's `DisposeAsync`).**
Rationale: the ruling says launch an instance when none is running, and a listener that fails proof *is* "none is running" — refusal would strand the agent while a zero-exposure route exists, and the warning keeps the state diagnosable (F38/F53 disclosure discipline).
Rejected: refuse-only (violates "launch instance only if none is running" and costs availability on any shared machine); silent fallback (the operator cannot tell why the backend is not on the configured port — the exact class of silence F38/N1 already ruled against); keeping never-attach as the default (the ruling overrules it).

Rationale: the measured invariant is "no secret reaches an unproven listener", which gating alone enforces; the token value, header (`McpTokenGate.HeaderName`, `McpTokenGate.cs:17`) and the `${AIRACCOON_MCP_TOKEN}` client contract (`McpEntryRenderer.cs:12-15`, `integrations/hermes/tests/test_integration.py:175-190`) survive untouched while the launch default reverts — two revolutions are not run in one change.
Rejected: deriving the channel token from the key and deleting the token file (one fewer secret, but it rewrites `McpTokenGate`, every agent config and the mint/heal machinery (`McpTokenFile.cs:54-128`) in the same breath as the launch revert); signature-per-request instead of a bearer token (wire rewrite across proxy, settings and restart with no ruling basis).

### d.2 Adversarial fixture spec (extends `tests/AiRaccoon.Tests/TestHelpers/`)

**`Squatter.cs` (today 124 lines: header-only capture at `:105-119`, `/mcp`+jsonrpc bait at `:17-22`) — extended, never replaced:**
- **Body capture**: record full request bodies (bounded 16 KB, overflow counted), alongside headers; `SecretBytesSeen(params string[] secrets)` scans every recorded byte for the minted token value, `BEGIN PRIVATE KEY` PEM markers and base64url keyIds. This closes the real hole: today's capture would hide a body-borne secret — T19 is the honesty gate that proves the detector can fail.
- **`ProofMode`** (one per hostile strategy, each a small adapter over the accept loop):
  `None` (404 on `/identity-proof`), `Forge` (independent `ECDsa` key, signs the transcript shape correctly but under the wrong key), `ForgeNoAudience` (fabricates without audience binding), `Replay(capturedBytes)` (returns a previously captured valid proof response verbatim — the replay fixture), `Relay(Uri backend)` (forwards the raw challenge to a live backend and returns its status + body — the relay fixture, pointed at another data root's backend or at the same root's other port), `ValidForAnotherRoot(IdentityKeyFile other)` (canned well-formed proof under root B's key), `Malformed(sub)` (`Html`, `Truncated`, `Empty`, `WrongVersion`, `Huge` = 8 MB), `Slow(delay)` (delays past the proof budget).
- **Partitioned recording**: `ProofRequests` / `NonProofRequests` + a `MustHaveSeenOnlyProofTraffic(secret…)` assertion used by every hostile gate (the "zero requests beyond the bounded challenge, zero secret bytes" enforcement point).

**`FakeRaccoon.cs` (today 115 lines: `/shutdown`-only token recording at `:33-41`) — becomes the honest-but-configurable listener:**
- ctor-level `IdentityKeyFile` + `ProofBehavior { Prove, Refuse, SignAnyAudience (cross-port relay enabler), Slow }` on a real `/identity-proof` endpoint (the `Prove` mode reuses production `IdentityProof` to sign; hostile modes sign with fixture-local crypto so a broken `IdentityProof.Verify` cannot make them pass).

### d.4 Honesty checks (a gate that cannot fail is a defect)
1. The hostile fixture's secret detector is itself gated (T19) and is red today — the capture must be able to see what the gates claim it sees.
2. Every hostile gate pairs with a positive control in the same fixture class that demonstrably produces the success shape (proven backend, real relay path, staged marker file, whole-root backup find).

## (e) Risks

1. **Rolling-upgrade skew from the F49 move.** A pre-change binary still running reads `mcp-token` from the old path (`McpTokenFile.cs:36-40`); the move-on-first-access keeps in-memory tokens working (the gate holds bytes at startup, `McpTokenGate.cs:47`) but an *old CLI* against a *new server* loses its file. Mitigation: move (not copy) + the how-to's upgrade note; residual accepted.
2. **First-run UX change (F39).** Quick Start's first command (`model embedding set local`, `README.md:61-65`) starts refusing on a fresh root until the documented `serve` bootstrap runs — a user-visible onboarding change the ruling forces ("must never mint"). Mitigation: T23/T41 gate the docs and the sequence together; the refusal's remedy line is the fallback documentation (F53).
3. **Unauthenticated signing oracle.** `/identity-proof` signs without a token (it must — it precedes any secret). Bounded to one fixed transcript shape over verifier nonces with platform ECDSA; a captured signature is replay-safe (nonce) and relay-safe (audience + key pinning), but the endpoint is new attack surface — recorded in the ADR revision and probed by T12/T13.
4. **Residual TOCTOU.** Proof-then-send shrinks but does not close the child-dies-and-a-racer-takes-the-port window ADR-0105 already documents ("Private channel and TOCTOU"); the unix-socket hardening stays future work.
5. **Fallback-instance multiplication on a squatted port.** Each client falls back to its own ephemeral backend against one bank — safe under WAL + `busy_timeout` (`SqliteConnectionFactory.cs:295,343-347`) but N instances can pile up; bounded by the 5-minute fallback idle timeout (D4).
6. **Squatted-port E2E flakiness.** Port races and spawn timing are the historical flake class (`LoopbackPort`, `ServeHarness`, `[RetryFact]` precedent); T25/T38 use `LoopbackPort.Reserve().ReleaseForBind()` and keep the R6 liveness half so a spawn failure can't pass a gate for the wrong reason.
7. **Exit-code surface is deliberately unchanged** (proof failures map to `PortInUse` 3 / `ProxyBackendUnavailable` 6 / `SettingsServerUnavailable` 18 / `NoBank` 22); if operators later need to script "impostor" distinctly, a new code is its own ruled change (the `HowToExitTableTests` registry, `docs/work/2026-09-22-project-scope-review/REVIEW-ASSEMBLED.md:806-810` question 5).
8. **LoggerMessageEventId registry churn** (ids 720-726 + `logging-event-ids.md`) — mechanical, gated by T36.
