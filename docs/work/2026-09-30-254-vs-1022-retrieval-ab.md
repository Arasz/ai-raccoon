## 3. Method

- **Frozen queries.** `scripts/retrieval_tuning/corpora/eval-set-100.json`, 100 queries (frozen
  texts; the eval-reanchor step changed zero `query` fields). Runner names passed to the server came
  from `/tmp/aira-ab-254-vs-1022/runner-corpus-100.json`.
- **Per-arm anchors.** Regenerated by `scripts/retrieval_tuning/build_eval_corpus.py` against each
  arm's bank (hash first, `expectedSource` fallback). The A/B basis is generator-consistent across
  arms by construction (eval-reanchor decisions doc).
- **Serving and scoring.** `scripts/retrieval_tuning/run_threshold_eval.py` driven by
  `/tmp/aira-ab-254-vs-1022/run_ab.py --repeat N --corpus runner-corpus-100.json --arms-spec
  arms-spec.json --out-dir runs/run-N` for N=1,2,3. 3 repeats x 100 queries, 100 pairs per
  repeat, both arms.
- **Repeats.** The three per-repeat metric sets are byte-identical per arm. Per-repeat spread in
  `metrics.json` carries `runValue`, `runSetMean`, `deltaFromRunSetMean`, and `runSetRange`; the
  aggregate `spread` carries `values`, `min`, `max`, `range`, `stddev`. Every range and stddev is
  0.0 for both arms.
- **Paired instrument.** `pairCount=100`; top-8 set overlap, RBO (p=0.9), and drop/backfill lists
  come from the same `runs/run-N/metrics.json` pairs. `assembled/paired.json` marks the instrument
  `reportedSeparately: never merged with the objective metrics or the blind grader result`.
- **Blind grader.** P4 sample selection reused verbatim from `committee_grade.py` (seed 42):
  stratification is mechanical top-8 set overlap only, `changed < 1.0`, `controls == 1.0`. The P4 to
  P5 bridge mirrors the integration-test contract; the grader pass is `ab_compare.run_ab` with the
  default seeded position randomisation (seed 20260909) and the real `pi -p` runner. Each query
  renders a payload that names the lists only `first`/`second`; the arm mapping is restored only in
  `ab-results.json`. A malformed response is re-asked once, then recorded as an abstention;
  `compScore = thresholdPicks / (3 - abstentions)`, never silently scored.
- **Host.** Serial queue g-2: the brief confirms the d-57 WebGPU footprint run completed before this
  lane started. At 14:37Z, as the blind re-run finished, `pgrep` showed no WebGPU or pytest workload;
  ambient housekeeping processes (`poll_limit.py`, the task-graph server, several `ai-raccoon` MCP
  stubs, MSBuild node reuse) were present.

## 5. Residual confounds

These must travel with any interpretation of the results.

**(a) arm-254 re-embedded under a distinct engine fingerprint (by construction, PR-3.R6).**
arm-254's fingerprint is `local:...arm-254/models/granite-embedding-small-english-r2#777268daa83ea925bfbfe4e020e62d0232be6df48189280a117a3de65bbd4ff6`;
arm-1022's is `local:bundled#ef600cb98e973722d33646a86640270a2a6a968f4842f55f60f7cd52d9e6a502`.
Editing `chunkTokens: 254` in the copied manifest changes its bytes, so
`EmbeddingManifestLoader` rejects the scratch directory unless it is re-embedded; arm-254 ran
`MarkAllEmbeddedPending`. The fingerprint delta is part of the treatment, not an accident, and the
A/B reads it as such.

**(b) Two paths carry content drift between arms.** `pi-badger-integration`
`docs/reference/extension-catalog.md` and `docs/howto/update-integrations.md` (2 of 5,514 distinct
paths) changed on disk at 11:34Z mid-re-chunk, and mirror groups re-read disk. Any regression query
whose ground truth touches either path is drift-confounded, not budget-caused. The drift check found
0 such regression queries (section 4.4).

**(c) G6: 32 migration tombstones for hashes absent from COPY1022. HYPOTHESIS: retry-window
intermediate chunks.** Between 13:00Z and 14:00Z arm-254 wrote 35 `sync_tombstones` rows, of which
32 have no hash twin in COPY1022's `entries` (read-only probe over both banks; the latest
`received_at` is 13:22:57Z). The proposed mechanism, retry-window intermediate chunks (windows
re-chunked 1066+3017 then 12 then 3 groups), is a HYPOTHESIS: it is consistent with the retry
bookkeeping but was not re-derived here.

**(d) E026 anchor drift from eval-reanchor.** The composite-label matcher resolves ADR families
against any pipe-separated section component; for E026 the generator's family-first-match rule picks
the merged `Context | Decision 1` chunk instead of the old `Decision 2` chunk. The anchor is not
hand-edited: the A/B regenerates `expectedHash` per arm with the same generator, so the cross-arm
basis stays generator-consistent. The query text is unchanged. The full disposition is in
`docs/work/2026-09-30-eval-reanchor-decisions.md`.

**Query trim moves with the budget by design.** The query trim is the chunk budget seen through the
same engine descriptor (`TrimQueryToWindow` uses `ManifestContentBudget`), so the 254 arm also trims
queries to 254 tokens and the 1022 arm to 1022 (ADR-0071 amendment 2026-09-23, ADR-0108 decision 5;
research record `docs/work/2026-09-28-why-the-query-budget-stays-254.md` F3). The query effect is
part of the budget treatment and was not measured separately.

2. G4 floor: the 254 budget is below the 0.5 mean-nDCG@5 floor on all three repeats; 1022 passes.
