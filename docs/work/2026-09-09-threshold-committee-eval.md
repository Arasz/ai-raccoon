## 6. Findings, limitations and hypotheses

1. **H1 (grader headless compatibility): PARTIALLY RESOLVED, ONE MODEL BLOCKED.** Graders
   #1/#2 accept the gated-form brief headless. Grader #3 is unreachable for an
   environmental reason (no provider credentials), which is an owner decision, not a
   harness defect: substitute a different third model, or provision a xiaomi key
   (`/login` → xiaomi, or `XIAOMI_API_KEY`) and re-run the H1 smoke. **No substitution was
   made.**
2. **Mechanical (final, n=100):** mean top-8 set overlap 0.976, mean RBO 0.5034, 15/100
   queries changed, 19 drops ↔ 19 backfills, anchor auto-grade 81/99 → 80/99. At τ=0.95
   the diversifier's top-8 footprint on this snapshot is small; its changes concentrate on
   generated/volatile files. Whether the changed queries differ in *quality* needs the
   committee — currently blocked.
3. **Scoping (new):** per-project scoping is load-bearing for large projects but is not a
   hard filter for 1-row projects (C034/C072 served cross-project chunks). Worth a
   dedicated probe before the next eval round; does not invalidate this run's arm
   comparison.
4. **H2 (paraphrase coverage): flagged.** ~18–19% of file-targeted anchors missed the
   top-8 even in the off arm; the committee's per-chunk grades would say whether the
   misses are query-side or rank-side — blocked with the fleet.
5. **H3 (snapshot drift): handled.** Fresh copy → corpus regenerated on it (100 queries,
   seed 42); snapshot sha recorded (setup block). The copy's file sha changed after the
   run (SQLite checkpoint on server exit); `make_memory_copy.py --verify-only` re-verified
   content identical to the live snapshot (53792 entries, 5/5 spot-checks) — both arms ran
   on the same content.
6. **Determinism note:** the regenerated corpus is NOT expected to be byte-identical to the
   committed `project-corpus-100.json` (different bank snapshot; the committed artifact
   remains the checked-in contract). The regenerated artifact is archived as
   [corpus-regenerated.json].
