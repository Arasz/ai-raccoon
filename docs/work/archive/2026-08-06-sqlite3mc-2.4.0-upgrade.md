# SQLite3MC 2.4.0 upgrade — what the new version gives us

Date: 2026-08-06 · Scope: SQLite3MC.PCLRaw.bundle 2.1.11-train → 2.4.0 (SQLite 3.49.1 → 3.53.4)

## What changed (package-level)

- `SQLitePCLRaw.bundle_e_sqlite3mc`/`provider.e_sqlite3mc` 2.1.11 (SourceGear train) replaced by
  `SQLite3MC.PCLRaw.bundle` 2.4.0 (utelle's own PCLRaw packages). SQLitePCLRaw's encryption bundles are deprecated since 3.0 (SourceGear announcement, 2026-08); utelle's train is the maintained one and requires `SQLitePCLRaw.core >= 3.0.2`
  (pinned 3.0.5 — satisfied).
- `Microsoft.Data.Sqlite` (full) → `Microsoft.Data.Sqlite.Core`: the full package drags the deprecated `SQLitePCLRaw.bundle_e_sqlite3` 2.1.11 (SQLCipher train, SQLite < 3.50.2) in transitively. Core + our own provider init
  (SqliteEncryptionInit) keeps exactly one native SQLite in the graph.
- Resolved graph after the change (measured, `project.assets.json`): `SQLite3MC.PCLRaw.bundle/
  lib/provider` 2.4.0 + `SQLitePCLRaw.core` 3.0.5 + `Microsoft.Data.Sqlite.Core` 10.0.10.
- NU1903 suppression removed: the vulnerable 2.1.11 train (GHSA-2m69-gcr7-jv3q / CVE-2025-6965)
  is out of the graph; 2.4.0 bundles SQLite 3.53.4.

## Measured facts (probe builds, 2026-08-06, arm64 macOS)

- 2.1.11 train: SQLite 3.49.1, default cipher **chacha20**, kdf_iter 64007.
- 2.4.0 train: SQLite 3.53.4, default cipher **chacha20**, kdf_iter 64007. The sqleet ChaCha20-Poly1305 scheme has been the SQLite3MC/wxSQLite3 default since wxSQLite3 4.0 (docs: ciphers/cipher_chacha20). The repo docs' "AES-256-CBC" claim
  was stale before this upgrade; corrected to chacha20.
- Cipher scheme is stored per-database and auto-detected on open: a bank created by the 2.1.11 train opens, reads, and re-verifies wrong-key rejection under 2.4.0 with no rekey (`/tmp` probe, both trains, same passphrase). Existing banks
  survive the upgrade.
- Compile options of the bundled lib (excerpt): FTS3/4/5, RTREE, GEOPOLY, MATH_FUNCTIONS, PERCENTILE, SESSION, SNAPSHOT, PREUPDATE_HOOK, CARRAY, COLUMN_METADATA, SECURE_DELETE, THREADSAFE=1, DEFAULT_FOREIGN_KEYS=ON, COMPILER=clang-21. No
  JSONB define (JSON1 always-on).
- Wrong passphrase still fails with SQLITE_NOTADB (26) — encryption active, no config change needed for the existing `Password`-only connection string.

## What we can use from 2.4.0

1. **SQLite 3.49.1 → 3.53.4 — security and correctness.** Fixes the suppressed CVE-2025-6965/GHSA-2m69-gcr7-jv3q and, importantly, 3.53.0's **WAL-reset database corruption bug** — AiRaccoon exercises that path: SyncService runs
   `PRAGMA wal_checkpoint(TRUNCATE)` on every sync and RekeyBankAsync switches journal modes. This alone justifies the upgrade.
2. **Rekey in WAL mode (2.4.0).** Previously rekey in WAL corrupted the bank; now supported but keeps the previous key salt. We keep the DELETE-journal rekey (fresh salt, plan §3.3) — no code change; comment in SqliteConnectionFactory
   updated to document the tradeoff.
3. **VLE — Value Level Encryption (2.4.0).** `sqlite3mc_vle_key/encrypt/decrypt` SQL functions encrypt individual column values (36-byte overhead/value; chacha20 or ascon128; key set per connection, independent of full-db encryption).
   Verified working on 2.4.0. Not adopted: the bank is either fully encrypted or plaintext, and VLE would need explicit encrypt/decrypt in every query on the protected column (no transparent column mapping). Reserve for a future
   "plaintext bank + protect only secrets" mode if one is ever wanted.
4. **Additional ciphers (2.2/2.3+):** AEGIS family and Ascon-128 for full-db encryption; also usable by VLE. Not adopted — switching cipher needs a rekey/migration and chacha20 is a fine default.
5. **ENABLE_SESSION compile option.** SQLite session/changeset API is compiled in but NOT reachable
   from Microsoft.Data.Sqlite 10.0.10 (no managed API — reflection-verified 2026-08-06). **CLOSED:**
   the delta-sync idea is dropped; see `docs/work/archive/2026-08-06-sqlite3mc-feature-surface.md` F8.
6. **sqlite3mc_version () / PRAGMA cipher introspection** — useful in diagnostics.

## Recommendations

- Keep the consolidated graph (one native SQLite family); bump `SQLite3MC.PCLRaw.bundle` when utelle publishes 2.5.0+ on NuGet (2.5.0 exists on GitHub 2026-08-02, not yet on NuGet).
- Do not add cipher pragmas; defaults are unchanged and existing banks are self-describing.
- Tests landed (2026-08-06): encrypted open/read/write, wrong-key rejection, and rekey round trip
  (SqliteConnectionFactoryEncryptionTests + EncryptionBitwardenIntegrationTests); sync checkpoint on
  an encrypted bank (SyncServiceEncryptedTests) — which exposed and fixed a real bug: sync on an
  encrypted bank failed with SQLITE_NOTADB at the unkeyed snapshot strip, now keyed throughout
  (feature-surface follow-up, task improve-sqlite).

`/tmp/sqlite3mc-old` (this machine, arm64).
