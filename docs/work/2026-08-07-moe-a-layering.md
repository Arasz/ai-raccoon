# MoE panel — Expert A: Layering & module boundaries

*Superseded 2026-08-08 by WI-8/WI-9/#151 shipping (PRs #161/#162/#163) — see 2026-08-07-moe-integrated-plan.md for current status.*

Date: 2026-08-07
Scope: the three-project split (`AiRaccoon.Core` / `AiRaccoon.Infrastructure` / `AiRaccoon`),
port/adapter discipline, folder naming, cohesion/coupling, god types, over-engineering.
Read-only review. Builds on `docs/work/2026-08-06-static-class-classification.md` (does not redo it).

## Verdict

The layer split is real and it holds where it matters most: `AiRaccoon.Core` has **zero**
`Microsoft.Extensions.*` usings, zero `ILogger`, zero `IHostedService`, zero `File`/`Directory`/
`HttpClient`/`Process`, no ambient `DateTime.UtcNow` and no `Guid.NewGuid` — time is injected as a
parameter everywhere. The Core `.csproj` has no `ProjectReference` at all, so the boundary is
compiler-enforced rather than convention-enforced, and the ports (`IMemoryStore`,
`IWorkspaceStore`, `IWatchService`) leak no SQL, connection, transaction, rowid, FTS, vec, pragma or
vacuum concept into a signature. That is better than most codebases of this size and it should not
be disturbed. The problems are all at the edges rather than in the trunk. Three of them are
concrete: an **MCP response envelope living in the domain layer** (`ApiEnvelope.cs` at Core's root,
whose own doc comment says "the MCP output schema derives from this record"), a **domain-layer
package reference that exists only as a conduit for the host** (`JetBrains.Annotations` is declared
on Core, used nowhere in Core, and consumed only by `src/AiRaccoon/Tools/*.cs`, whose own csproj
does not declare it), and **two dead islands** (`CloudSyncConnection`/`Factory`, `RuntimePlatform`).
Beyond those, the codebase carries more abstraction than it has buyers for: 12 of 26 interfaces have
neither a second production implementation nor a test double, and a ~230-line plugin mechanism
(`IMemoryExtension` + `MemoryExtensionHost` + `RetrievalRatingExtension`) whose only plugin has a
literal no-op in every hook. `SqliteMemoryStore` at 1227 lines is genuinely a god type, but the
correct seam is *not* the SQL — the class is two adapters welded together, a persistence adapter and
a filesystem-ingestion adapter, and `IMemoryStore` carries `IngestFileAsync`/`IngestDirectoryAsync`
as a consequence. Fix the boundary and the size follows.

### Findings I tried to make and dropped

- *"Core does I/O via `Path.GetFullPath`"* (`Watch/WatchPath.cs:22`, `Watch/WatchScopeList.cs:35,49`) — re-read: `Path.GetFullPath` reads the process CWD, so it is not referentially transparent, but it performs no filesystem access. Path normalisation is legitimately domain logic here. Not a violation; dropped.
- *"MCP layer holds business logic"* — re-read `src/AiRaccoon/Tools/MemoryTools.cs:49-88` and the file's shape: every tool is guard → validate → delegate → wrap, with `ToolExecutionActivity` for tracing and no branching on business rules. At 358 lines for 9 tools it is verbose from `[Description]` attributes, not from logic. The invariant holds; dropped.
- *"The three-project split is over-engineered for 13.5k LOC"* — re-read `Core.csproj`: no `ProjectReference`, three packages, and the purity sweep came back clean on every axis. The split is compiler-enforcing a real invariant, not decorating one. Dropped.
- *"`IPromotionQueueMetrics` is an abstraction with no buyer"* — it is implemented in `src/AiRaccoon/Observability/PromotionQueueMetrics.cs:12`, which lives in the **host** project that Core and Infrastructure cannot reference, and it is genuinely substituted by `RecordingMetrics` (`PromotionQueueServiceTests.cs:239`). It earns its keep twice over. Dropped.
- *"`Options/`, `Setup/`, `Observability/`, `Tools/` are technical-bucket drift"* — these are the sanctioned chassis exception (DI wiring, CLI/host composition, telemetry, protocol surface). `Tools/` in particular is the MCP protocol's own vocabulary, not a generic bucket. Dropped; see "What is already good".

## What is already good — do not touch

- **Core purity is real and compiler-enforced.** `AiRaccoon.Core.csproj` declares no `ProjectReference` and exactly three packages. The sweep found zero `Microsoft.Extensions.*`, zero `ILogger`/`IHostedService`/`IServiceCollection`/`IConfiguration`/`IOptions`, zero `File`/`Directory`/`FileStream`/`HttpClient`/`Process`/`Environment.GetEnvironmentVariable`. Whatever else changes, keep this property.
- **Time is injected, never ambient.** Zero `DateTime.UtcNow`/`DateTimeOffset.UtcNow`/`Guid.NewGuid`/`Random` in Core; `DateTimeOffset` appears only as a parameter (`SharedExtractionService.cs:26`, `IWorkspaceStore.cs:10,13`). Infrastructure uses injected `TimeProvider`. This is the single biggest reason the domain logic is testable — do not regress it.
- **Port altitude is clean.** All 23 `IMemoryStore` signatures, both `IWorkspaceStore` signatures and all five `IWatchService` signatures are domain-shaped; not one names a table, transaction, connection, rowid, FTS/vec concept, pragma or vacuum. `IWatchService.cs:5` even states the intent ("Core types only — infrastructure-free") and the code honours it. A-06 is a *size* complaint, not an altitude one.
- **The MCP layer is genuinely thin.** `MemoryTools` is guard → validate → delegate → wrap with no business branching (`MemoryTools.cs:49-88` is the representative shape). ADR-0001's rule that validators fire at the tool boundary is followed exactly, and FluentValidation has not spread past the two types the ADR named (`SearchQuery.cs:47`, `MemoryWriteRequest.cs:14`).
- **The search pipeline is already well-extracted.** ~1200 lines of pure helpers sit outside `SqliteMemoryStore` (`FtsQueryNormalizer`, `SourcePathQuery`, `SearchContexts`, `ReciprocalRankFusion`, `SearchResultMerger`, `SourceAffinityRanker`, `SnippetFallback`, `StructureFusion`, `ContextResolver`, `LikePattern`). `SearchAsync` is now mostly orchestration of these. The remaining god-type problem is the ingestion/settings boundary (A-05, A-06), **not** the search path — do not "refactor search" as part of this.
- **The sibling stores are the right pattern and already correct.** `SqliteWorkspaceStore` (51 lines) and `SqlitePromotionQueueStore` (130 lines) are each one aggregate behind one narrow port, sharing only `SqliteConnectionFactory`. R8 should copy them, not redesign them.
- **The domain folder names scream.** `Memory`, `Workspace`, `Promotion`, `Watch`, `Sync`, `Extraction`, `Degradation`, `Rating`, `Chunking`, `Encryption`, `Maintenance` all name what the system does. `Setup/`, `Options/`, `Observability/`, `Tools/` are the sanctioned chassis exception (host composition, config records, telemetry, MCP protocol surface). Only `Common/` is drift, and R3 empties it.

## Durable project facts

- Core's layer purity is enforced structurally, not by convention: `src/AiRaccoon.Core/AiRaccoon.Core.csproj` has **no `ProjectReference`** and exactly three `PackageReference`s (FluentValidation, JetBrains.Annotations, CommunityToolkit.Diagnostics). Any new Core dependency needs an ADR — ADR-0001 is the precedent and covers FluentValidation only. Source: `src/AiRaccoon.Core/AiRaccoon.Core.csproj`, `docs/adr/0001-fluentvalidation-in-core.md`.
- `JetBrains.Annotations` is declared on **Core** but used only in `src/AiRaccoon/Tools/*.cs`; the host csproj does not declare it and relies on the transitive flow through Core. Source: `src/AiRaccoon.Core/AiRaccoon.Core.csproj:12`, `src/AiRaccoon/Tools/MemoryTools.cs:9`, `src/AiRaccoon/AiRaccoon.csproj`.
- `ApiEnvelope<TData>` / `ResponseMeta` live at the **root of Core** (no folder) and are the source of the MCP tool output schema; `ResponseMeta` also appears in the Core port `IPromotionQueue.GetMetaAsync`. Moving them is an MCP wire-contract change, not a refactor. Source: `src/AiRaccoon.Core/ApiEnvelope.cs:1-17`, `src/AiRaccoon.Core/Memory/IPromotionQueue.cs:28`.
- `IMemoryStore` has **23 methods across ~9 concerns**, but every consumer except the `MemoryExtensionHost` decorator uses a 1-4 method slice; ten callers use only the four settings methods. Source: `src/AiRaccoon.Core/Memory/IMemoryStore.cs:4-88`, `src/AiRaccoon.Core/Rating/MemoryExtensionHost.cs:10-148`.
- `SqliteMemoryStore` (1227 lines) is two adapters in one: SQLite persistence **and** filesystem ingestion (`File.ReadAllTextAsync` at `:425`/`:443`, `Directory.EnumerateFiles` at `:435`). The concern seam, not the SQL, is why it is large. Its only shared spine is the `factory` field (used by all clusters); `chunker` is write-only, `embeddings` spans two clusters, `timeProvider` three. Source: `src/AiRaccoon.Infrastructure/Sqlite/SqliteMemoryStore.cs:19-24,414-449`.

- Of 26 interfaces in `src/`, **12 have neither a second production implementation nor a test double**: `IEvictionPolicy`, `IPromotionQueueStore`, `IMemoryExtension`, `ICloudSyncConnection`, `ICloudSyncConnectionFactory`, the six `I*Commands`, and `IActivitySignaler`. Only two are genuine strategy points (`IEncryptionKeyProvider` with 3 impls, `ICloudStore` with 3). Source: full inventory in this document's Findings; declarations under `src/AiRaccoon.Core/`, `src/AiRaccoon.Infrastructure/`, `src/AiRaccoon/`.
