# MoE Panel — Expert F: Documentation, ADR Conformance, Knowledge Hygiene

> Full-project review of AiRaccoon's docs tree (~115 files) against `src/`. Produced by
> three parallel sub-agents (ADR conformance, `docs/work/` disposition, entry-doc +
> Diátaxis + cross-linking) plus lead-agent direct verification of the tool surface.
> All code citations were re-verified against `src/`, not taken from doc prose.

## Verdict

The architectural core is in excellent shape — all 7 ADRs hold against current code with
zero drift, every tool is instrumented (ADR-0002), every response is enveloped
(ADR-0007), and the three "tensions" flagged for investigation (FluentValidation in the
domain layer, "fixed" vs configurable alpha, minScore 0.0 vs 0.7) turn out to be
deliberately reconciled inside the ADRs' own text, not silent drift. The failure mode
here is not architectural rot, it's **bookkeeping rot**: a stale tool count ("17"/"19"/"20"
instead of the real 22) has propagated independently into four separate files (README,
architecture.md, docs/reference/README.md, SECURITY.md), the tool contract doc is
entirely missing two live, shipped MCP tools, `docs/work/README.md` claims its directory
is empty when it holds ~90 files, and a design document for an unrelated project
(`job-search-ai-assistant`) is filed under this repo's `docs/design/`. `docs/work/` itself
is a coherent, well-attributable sprint archive — 45 of 60 files are correctly disposed
of as `archive` (their conclusions already live in ADRs/reference docs), only one
(`2026-08-07-bank-maintenance-design.md`) documents a shipped decision that needs an ADR
of its own, and the `tutorials/`/`how-to/` quadrants are genuinely near-empty for a tool
shipping encryption, cloud sync, two transports, and a CLI.
