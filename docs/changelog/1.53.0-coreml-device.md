# 1.53.0: an opt-in `coreml` device runs the bundled engine on the Neural Engine

Feature release, shipped by PR #769 (#764 stage 3). Decision: [ADR-0118](../adr/0118-opt-in-coreml-device-on-the-neural-engine.md), superseding [ADR-0117](../adr/0117-coreml-execution-provider-stays-out.md).

- `ai-raccoon settings model device coreml` runs the bundled engine through the CoreML execution
  provider on the Neural Engine, on osx-arm64 only. It applies to the bundled model only; a
  downloaded model ignores it and keeps running on the CPU, the same way it ignores `mlx`. Off
  osx-arm64, or with the graph missing, the setting is refused with a reason and the existing
  WebGPU-then-CPU chain runs.
- The first start after opting in compiles four sessions in the background, one per length bucket
  (256, 512, 768 and 1024 tokens): about 35 seconds cold on an M4, 0.7 seconds warm. WebGPU keeps
  serving until every bucket loads and a parity probe (cosine at least 0.999) passes; a load
  failure, timeout or probe miss falls back to WebGPU with a logged reason. Rows over 1024 tokens
  run on a plain CPU session.
- Measured on an M4: 6-8% of MLX's CPU-seconds, 0.49-0.57 GiB of phys+neural memory, recall
  unchanged, and the Neural Engine rail at 1276 mW while the graph runs. The compiled cache costs
  about 808 MiB in `<data-root>/coreml-cache/`; `ai-raccoon doctor` reports its state and size.
- The package grows by 5.7 MB for the CoreML graph, which reads the weights file the bundled
  engine already ships. The engine fingerprint is unchanged, so no bank re-embeds when switching
  devices, in either direction.
- ONNX Runtime's own telemetry is now turned off (`DisableTelemetryEvents`) before the first
  session is created, on every device. Its HTTP worker aborted the process at exit (exit 134,
  `recursive_mutex lock failed`) once both MLX and CoreML had been loaded, and AiRaccoon had never
  meant to run it.
- `ai-raccoon doctor` prints a `coreml:` line when the device is `coreml` or a CoreML cache exists:
  the compile state, its trigger and reason, the owning pid, and the cache size.
- Making `coreml` the Apple Silicon default is a separate, later decision, gated on a second chip,
  an in-product A/B against WebGPU, and a release of opt-in use.
