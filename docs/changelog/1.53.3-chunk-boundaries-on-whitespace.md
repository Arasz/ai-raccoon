# 1.53.3: long notes no longer split a word across two chunks

Fix release.

- A note or file line longer than the embedding budget is now split at the last space inside the
  budget instead of wherever the budget ran out. Before, an identifier on the boundary could end
  up half in one chunk and half in the next ("reference vk" | "83jq was filed"), and a keyword
  search for it found nothing. A line with no spaces (a URL, minified JSON) is split between
  search terms instead. The same rule applies inside code fences and to the code index.
- A single term longer than the whole budget still has to be cut, but a search for it now finds
  it: a query term over 64 characters matches by its first 64.
- Existing banks repair themselves once, on the first maintenance pass after the upgrade. Files
  with a word cut across two rows are re-ingested from disk, watched files included, and notes
  are re-chunked from their stored rows. The repaired rows are embedded again in the same pass.
  A note's first-row hash can change as a result (ADR-0120).
