# 1.55.3: `repair project-ids` handler split into named steps

Refactor release. No output, exit code or request changes.

- `ProjectIdsRepairCommands.RunAsync` shrinks from 163 lines to 43. It now reads as the command's
  steps: load the map, write the scoreboard, write the per-id buckets, write the template note on
  a map-less dry run, then end in a dry-run summary, the queue-only request, or the repair loop.
- The `--queue-only` path is one method, `RequestOnceAsync`. It used to count the actionable changes
  twice, once in `RunAsync` and again inside the helper it called.
- A new whole-transcript test, `ProjectIdsRepairTranscriptTests`, pins every output line, the exit
  code and the committed request for nine paths through the command.
