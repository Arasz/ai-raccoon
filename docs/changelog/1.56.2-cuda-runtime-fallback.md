# 1.56.2: recover CUDA failures during embedding

Fix release. No tool schema or settings changes.

- A CUDA session can build successfully and still fail when its first inference loads cuDNN.
  Native provider failures during inference now switch the generator to its configured
  WebGPU/CPU fallback, retry the failed row once, and keep later calls on the fallback.
  The warning includes the CUDA failure and the selected provider.
- Session replacement and disposal are serialized with inference so concurrent embedding calls
  share one transition and cannot dispose a session while its output is being consumed.
- The Windows CUDA setup guide now requires CUDA/cuDNN DLL directories on the server process’s
  inherited `PATH`, including the directory containing `cudnn64_9.dll`. Supplying only an absolute
  CUDA provider DLL path is insufficient.
