# 2.10.1: a watch change in this server applies at once, and the ignore rules never keep a stale parse

Fixes for two gaps the 2.10.0 review found. No schema change.

- **A watch added, removed or enabled in the server process applies at once.** `add_watch` registers the watch and
  returns; the OS watcher and the initial scan start in the watch loop's reconcile pass. 2.10.0 moved that pass to
  every 10 seconds, so a registration written just after a pass waited for the rest of the interval — up to 10 seconds
  on a path the caller had just asked to watch. The loop now waits for the first of the interval or a wake request,
  and an in-process `add_watch`, `remove_watch`, or server-side write of a watch-enabled setting requests one. The
  10-second interval now bounds only a change that another process made.
- **`remove_watch` stops the OS watcher at once.** The registration left the active set before the stale-registration
  sweep could see it, so the watcher kept delivering events until the server stopped.
- **The ignore rules can no longer keep the parse from before a change.** `IgnoreRulesProvider` now caches each root's
  rules behind an `IChangeToken` taken *before* the file is read — the shape `FileConfigurationProvider` uses — so a
  change that lands during a read fires the token and the next load reads again. The token is the file provider's
  own watch token composed with a per-root invalidation token that an edit, a rename, or a delete of the ignore file
  cancels. `ai-raccoon.ignore` is read through a polling `PhysicalFileProvider`, which creates no `FileSystemWatcher`
  and so does not duplicate the event stream 2.10.0 set out to reduce. A root that no watch covers reads an edit at
  the next load, at most 4 seconds late. The hand-written stamp check and generation counter are gone, and the guard
  they carried is now testable: the tests fire the token while a fake provider serves the read.
- **The ignore-file name is matched case-insensitively on Windows and macOS.** The default volumes on both hosts
  ignore case, so a file the loader reads as the rules file is also recognised as that file when it is renamed or
  deleted.
