# 1.50.1: the server no longer burns CPU on watched-repo churn

Fix-only release, shipped by PR #741.

- Excluded paths skip the delete cascade. A write under `.git`, `.ai-badger`, `bin`/`obj` or any
  hidden directory in a watched repo used to run the full path delete. It removed nothing, yet cost
  up to 0.9 s on a warm disk (far more after a reboot) and held the bank's write lock. Now only a
  path that was indexed before its exclusion rule matched gets cleaned.
- Path deletes seek an index. Removing a file's or a directory's rows takes two seeks on
  `(project_id, path)` instead of reading every row of the project. The bank gains
  `idx_entries_project_path` on first open. Subtree matching is now case-sensitive, like the
  exact-path match always was.
- Pooled bank connections initialise once. A re-opened connection no longer reloads the vector
  extension or repeats the schema pass. The idle watch loop opens the bank about 30 times a
  second, so this was most of its CPU.
