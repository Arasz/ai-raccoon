# 2.2.1: the Neural Engine cache no longer grows with every tool update

Fix. Under `device coreml`, `<data-root>/coreml-cache/` was meant to hold about 808 MiB: one
compiled model per bucket, four buckets. Instead every `dotnet tool update` added another
~198 MiB per bucket and nothing removed the old ones; one machine reached 13 GB after 17 releases.
Each update also paid a full cold Neural Engine compile instead of a warm load.

ONNX Runtime's CoreML provider names each compiled model after a hash of the graph's file path,
and a tool update installs the graph under a new versioned path. Two changes:

- **Stable key.** The bundled `model_fp16_ane.onnx` now carries `COREML_CACHE_KEY` metadata
  (`graniteR2ane`), so ONNX Runtime names the compiled model after the key and every install path
  reuses it. A tool update after this one loads warm.
- **Cleanup.** After the sessions load, each bucket's compiled models whose source graph no longer
  exists — one per uninstalled tool version — are deleted, and logged as event 440.

Because the graph changed, the first start of 2.2.1 under `device coreml` compiles once more. The
old cache set is deleted once no running server of an earlier version still holds it, which returns
the space.
