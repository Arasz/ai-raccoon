# 1.53.13: the context key is total over a NULL project id

Fix release.

- A memory entry whose `project_id` is missing no longer breaks the vector index. The SQL context
  key (`project_id` concatenated into the vec0 `ctx` column) returned NULL for such a row while its
  C# twin never did; vec0's metadata column rejects NULL, so embedding such a row threw
  (`Expected text for TEXT metadata column ctx, received NULL`), the embed-drain retried it and
  abandoned it after three attempts, and a pre-9 bank holding one such row could not be opened at
  all — the v9 rebuild rethrows on the NULL. Every concatenating branch now normalizes a missing
  project id to the empty string, so the key is `project:`, `custom:0::<label>` or
  `workspace:0::<id>` — the same key search-side code builds, and never NULL (ADR-0124, #801).
- The fix reaches banks that already exist. The trigger bodies that write `ctx` live in the bank
  (`sqlite_master`), and `CREATE TRIGGER IF NOT EXISTS` can only create, so every bank open now
  probes both trigger bodies and replaces them when they still carry the old expression — the same
  no-write-when-correct shape as the promotion-queue trigger repair, with the trigger DDL declared
  once so the stored body and the intended body cannot drift. No schema-version bump, no migration
  job (#801).
- Chunk-column maintenance now numbers a partition with no project id at its normalized key, and
  two differently-labelled contexts that both lack a project id are numbered separately instead of
  cross-numbering under one NULL group (#801).
