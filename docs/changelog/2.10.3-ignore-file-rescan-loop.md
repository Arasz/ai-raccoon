# 2.10.3: an unchanged ignore file no longer re-scans its watch

A fix. No schema change.

- **A watch whose root holds `ai-raccoon.ignore` no longer re-scans its tree about every 1.5 s.** The digest of
  the ignore file ran a 0-row replace-by-path (no corpus takes the file), kept no usable fingerprint and queued a
  full rescan, and that rescan digested the ignore file again. Each pass held the write lock and logged EventId 899
  with `0 row(s) written`. The ignore file now keeps its real hash: an unchanged file starts no scan, and an edit
  starts exactly one.
- **A file whose content decodes to an unpaired surrogate no longer fails its whole watch.** A JSON property name
  or a notebook cell holding an escape such as `\uD83D` made the tokenizer's `string.Normalize` throw, and the
  watch went to `retrying`. The bundled tokenizer now reads the unpaired surrogate as U+FFFD, and the file is
  indexed. A notebook cell still failed until 2.10.4.
- **A digest failure names its file.** `lastError` in the watch status is `<path>: <message>`, and the failure is
  logged with its exception as EventId 304.
