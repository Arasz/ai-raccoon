# 1.57.2: failed backend identification no longer starts another server

Fix release. The identity proof protocol is unchanged.

- A proxy or settings command facing an unproven listener now refuses with
  `Server.Unproven` (50), preserving the proof reason. It no longer starts a private
  backend on an ephemeral port when a running server fails identification.
- Automatic startup requires confirmed connection refusal. Timeouts, resets and
  foreign HTTP responses cannot authorize a backend launch, including at the
  launcher's second probe. Failed proof after a shared start never starts another.
- Reopen repeats the same policy. Shared backends keep their idle-watchdog lifetime;
  the removed private-backend cleanup path does not affect them. Error 64 remains
  reserved for the retired private-fallback failure.

See [ADR-0128](../adr/0128-refuse-unproven-backend-without-private-fallback.md).
