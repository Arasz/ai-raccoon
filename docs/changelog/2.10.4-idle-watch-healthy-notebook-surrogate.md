# 2.10.4: an idle watch reads Healthy after a restart, a notebook with a lone surrogate is indexed

A fix. No schema change.

- **A watch with nothing to catch up reads `Healthy` after a server restart.** A catch-up scan that found no changed
  file queued no digest, and only a digest moved a watch out of `Scanning`. `get_watch_status` and `watch status` then
  showed `scanning` and `lastSync: never` until the next file change. A scan that queues nothing now sets `Healthy` and
  a `lastSync`. A `Retrying` watch stays `Retrying`, because an idle scan does not prove recovery (#971).
- **A notebook cell with an unpaired surrogate escape no longer fails its watch.** 2.10.3 fixed this for JSON files,
  but a notebook failed earlier: reading the cell text threw `Cannot read invalid UTF-16 JSON text as string`. The cell
  text now reads the unpaired surrogate as U+FFFD, and the notebook is indexed (#970). The 2.10.3 release notes said
  notebooks were fixed; that was true only from this release.
- **A bank with no embedding engine no longer logs a drain warning on every pass.** Before `model embedding set`, each
  memory embed-drain pass logged EventId 1005 at Warning with an `Unknown embedding provider` stack. The drain now
  skips the pass; rows stay pending until an engine is set (#973).
