# 1.51.0: the GPU on Windows and Linux, and CUDA as an opt-in

Feature release, shipped by PR #740. Decision: [ADR-0112](../adr/0112-webgpu-plugin-off-macos-and-opt-in-cuda.md).

- Windows and Linux try the GPU before the CPU. The bundled engine now goes through the
  `Microsoft.ML.OnnxRuntime.EP.WebGpu` 0.4.0 plugin, packaged for `win-x64`, `win-arm64`,
  `linux-x64` and `linux-arm64` under `webgpu/`. macOS keeps ORT's built-in WebGPU;
  `linux-musl-x64` stays on the CPU (the plugin has no musl build). Linux needs the Vulkan loader
  `libvulkan.so.1` and a Vulkan driver; Windows needs a D3D12 driver. Without them the session
  falls back to the CPU and says why.
- CUDA is opt-in: `ai-raccoon settings model device cuda <absolute path to the provider library>`.
  The provider comes from `Microsoft.ML.OnnxRuntime.Gpu.Linux` or `.Gpu.Windows` 1.30.0 (it must
  match the core) and needs an NVIDIA driver, CUDA 13 and cuDNN (9, inferred from ORT's published
  1.27-1.29 table). It is never bundled: the provider alone is 272 MB, over nuget.org's limit. A
  refused CUDA attempt falls back to WebGPU, then the CPU.
- The "execution provider" log line names where each session landed and why the others were
  refused, for example `WebGPU (CUDA refused: provider library not found: <path>)` or, on a Linux
  host with no Vulkan driver, `CPU (GPU refused: … Failed to get a WebGPU adapter: No supported
  adapters)`. A GPU attempt never fails the session.
- Not measured: speed and vector parity on Windows D3D12 or Linux Vulkan GPUs, and CUDA loading as
  a plugin against the CPU core. No such hardware was available; report surprises on the
  repository. The engine fingerprint is unchanged, so no bank re-embeds.
- The win and linux packages grow by 14-35 MB each.
