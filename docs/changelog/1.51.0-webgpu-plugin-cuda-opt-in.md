# 1.51.0 — WebGPU plugin off macOS, CUDA opt-in

[ADR-0112](../adr/0112-webgpu-plugin-off-macos-and-opt-in-cuda.md)

## What changed

Windows and Linux embedding sessions try a GPU execution provider before the CPU now, the
same way macOS already did. Windows and Linux get it through a separate, packaged plugin,
`Microsoft.ML.OnnxRuntime.EP.WebGpu` 0.4.0, built for `win-x64`, `win-arm64`, `linux-x64` and
`linux-arm64`; `osx-arm64` keeps its existing built-in WebGPU path untouched, and
`linux-musl-x64` stays CPU-only, since the plugin has no musl build.

CUDA becomes a fourth device value, opt-in and never bundled:

```bash
ai-raccoon settings model device cuda /abs/path/to/libonnxruntime_providers_cuda.so   # Linux
ai-raccoon settings model device cuda C:\path\to\onnxruntime_providers_cuda.dll        # Windows
```

The provider library has to match this build's ONNX Runtime core exactly (1.30.0) and comes
from `Microsoft.ML.OnnxRuntime.Gpu.Linux` or `.Gpu.Windows` — it is never part of the tool
package, since the CUDA provider alone is 272 MB, past what nuget.org allows for one package.
It also needs `onnxruntime_providers_shared`, already shipped beside the tool, and may refuse
to load on a version mismatch between the two. `cuda` applies to every local model, not only
the bundled one. A stored path that is not absolute is refused the same way, with
`provider library path must be absolute: <path>` — defense against a hand-edited settings file,
since the CLI always stores an absolute one.

A session now tries, in order: MLX (opt-in, bundled engine, osx-arm64 only), CUDA (opt-in),
WebGPU, then the CPU. The "execution provider" line in the session-created log names which one
it landed on and, for every GPU candidate it tried and lost, why — for example
`"WebGPU (CUDA refused: provider library not found: <path>)"` or, on a Linux host with no
Vulkan loader, `"CPU (GPU refused: no WebGPU GPU device after registration (Linux needs
libvulkan.so.1)) (CUDA refused: …)"`. A session never throws because a GPU attempt failed.

## Host requirements

- **Windows** — a GPU driver with D3D12 support for WebGPU.
- **Linux** — the system Vulkan loader, `libvulkan.so.1` (`apt install libvulkan1` or the
  distro equivalent), plus the vendor's own Vulkan driver, for WebGPU. ONNX Runtime does not
  fall back to the CPU on its own when the loader is missing; this code does, once it finds no
  WebGPU device.
- **CUDA** (x64 only) — an NVIDIA driver, CUDA 13, and — unverified for ONNX Runtime 1.30
  specifically — cuDNN 9, inferred from the published requirements for 1.27.x through 1.29.x
  against CUDA 13.0.

## Not measured

Speed and vector parity on a real Windows D3D12 GPU or a real Linux Vulkan GPU. No such
machine was available while building this. Whether CUDA actually registers as a plugin
against this build's unmodified CPU core is unverified for the same reason — no NVIDIA host
was available. Report anything unexpected on the repository.

## Package size

`win-x64`, `win-arm64`, `linux-x64` and `linux-arm64` each grow by roughly 14-35 MB, for the
plugin file plus, on Windows, `dxcompiler.dll` and `dxil.dll`. `osx-arm64` and
`linux-musl-x64` are unaffected. The engine fingerprint does not change, so no bank re-embeds
because of this release.
