# 2.9.0: a row keeps its declared kind, and the bank guards it

Feature release. The bank migrates to schema v24 on first start.

- `get_entry` output has a new field `corpus` (`memory` or `code`). The output field `entryType` is deprecated: it has the same value as `corpus` and is removed in 3.0.0. Read `entryKind` for the kind of the row (#947).
- Schema v24: the bank refuses a TTL on any row that is not a memory row, and refuses an unknown kind. The migration clears the TTL of every non-memory row once. Memory-row TTLs stay.
- `ai-raccoon doctor` reports the number of rows that have a TTL but are not memory rows, and reports a missing guard trigger.
- Closing a workspace and `share_memory` keep the declared kind of each row. Before, a `file` row became a `memory` row in the copy. No copy carries a TTL.
- A re-ingest of a file keeps the declared kind and the TTL of the row. Before, a plain re-ingest could turn a memory row into a `file` row and drop its TTL.
- Internal: one list of vec tables for the schema steps, the reconciler and the trigger check. One `ToolNames` list for the MCP tool names, checked by a test against the generated tool inventory. The unused sweep-threshold gate (`trigger_memory_cleanup_threshold`, not a tool) is removed. No tool or setting changes.
