# 1.59.1: a tool call the caller gave up on no longer logs a stack trace

Fix release. No tool schema or settings changes.

- When the client cancels a tool call (for example `memory_search` hitting the client's own timeout
  while the query embedding runs), the MCP SDK logged "request handler failed" at warn with the full
  stack trace on every timeout. The server now drops that one SDK record when its exception is a
  cancellation; any other handler failure is still logged.
- The existing timeout line (EventId 914, or 915 for a tool without a query) is the only record:
  tool, elapsed milliseconds and query length. The call is answered with a `cancelled:` error result,
  as a call cancelled with the connection still live already was; the SDK sends nothing to a client
  that cancelled.
