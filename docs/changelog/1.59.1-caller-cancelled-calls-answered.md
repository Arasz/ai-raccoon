# 1.59.1: a tool call the caller gave up on no longer logs a stack trace

Fix release. No tool schema or settings changes.

- When the client cancels a tool call (for example `memory_search` hitting the client's own timeout
  while the query embedding runs), the server now answers it with a `cancelled:` error result instead
  of rethrowing. Before, the rethrown `TaskCanceledException` reached the MCP SDK, which logged
  "request handler failed" at warn with the full stack trace on every timeout.
- The existing timeout line (EventId 914, or 915 for a tool without a query) is now the only record:
  tool, elapsed milliseconds and query length. Nothing is sent back to the client either way — the
  SDK drops the response for a request the client cancelled.
