# 1.53.4: restart catch-up re-digests files whose live event was missed

Fix release.

- A watched file whose change event never reached the server (a `git checkout` burst, a digest
  that failed, a watch stopped after five failures) now gets re-digested on the next restart. Until
  now the restart scan compared each file's mtime with the watch's last-change time, which every
  digest of any other file moves forward. One later digest of a sibling hid the missed file for
  good. The scan now compares each file with the time its own fingerprint was written
  ([ADR-0121](../adr/0121-restart-catch-up-compares-each-file-with-its-own-fingerprint.md)).
- Banks that already hold stale files heal on the first restart after the upgrade. No command is
  needed. The scan does the same work per file as before.
