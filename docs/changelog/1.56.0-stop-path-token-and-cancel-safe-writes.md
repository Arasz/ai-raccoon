# 1.56.0: stop-path secrets ride the proven connection; cancel-safe writes everywhere

Fix release. Ships #831, #834, #835, #836 and #837, plus #832 and #833 (docs).

- **The stop token goes to the proven server or to nobody** (#837). When the proxy disposed a
  private backend, and on `serve --restart`, the identity proof and the token-bearing `/shutdown`
  (and, for a restart, the identify call) travelled on different connections. A backend that had
  just closed its listener could still pass the proof on its old keep-alive connection while a new
  connection for `/shutdown` reached whatever process had taken the port, which then received the
  token. Both paths now prove over a single-connection client and send their secret-bearing
  requests on that same connection; if it has closed, the request fails instead of re-dialling.
  ADR-0106's residual 2 now records the narrower scope (MCP session traffic and acquire-time attach
  still use pooled connections).
- **A cancelled replace no longer leaves its connection inside a transaction** (#836). The two
  replace-path transactions in `SqliteMemoryStore.Replace.cs` rolled back with the caller's token,
  so a write cancelled mid-flight could return a pooled connection with its transaction still open,
  failing the next borrower and blocking other writers with `SQLITE_BUSY`. They now roll back with
  an uncancellable token, like every other writer since 1.55.6.
- **Settings reads all go through one reader** (#836). The six remaining raw settings queries
  (bank maintenance intervals, the maintenance jobs, the repair family's chunk budget, the startup
  engine report) use `SettingsReader`, and the repair family and the ingestor share one chunk-budget
  resolution. Source gates now fail CI if a private `Def(`, a hand-written `BEGIN IMMEDIATE` or a
  raw settings read reappears outside its one home.
- **Integer setters parse invariantly** (#836): `settings performance|maintenance|extract` values
  are parsed and printed with the invariant culture.
- **A settings verb against a data root with no bank exits 31 (NoBank) however the CLI was
  launched** (#831). Under `dotnet run` or `dotnet exec` it used to exit 66 (AutoStartUnsupported).
- **Tests and CI** (#831, #834, #835): the packed-version test shows the pack's own output when it
  fails; two Python tests no longer depend on suite order or a named branch; `SyncTestBank` loads
  vec0 like production; the token-refusal clearing from 1.55.6 has a test; the duplication gate's
  ceiling is ratcheted from 1% to 0.6%.
