# 2.6.1: decision tools match their output schema

Fix release.

- Claude Code rejected the replies of the decision tools. Each tool's `outputSchema` lists nullable
  fields (such as `changeReason` and `nextAfterId`) as required, but the reply left null fields out. The
  write had already committed, so the caller saw an error for work that succeeded. Replies now carry
  those fields as `null`.
- A refused decision call now also carries a structured `error` with `kind` and `message`. The text is
  unchanged (`<kind>: <message>`).
- Range refusals name the inclusive bounds. Graph depth now reads "between or equal to 0 and 10" where
  it used to read "in the range given by 0 and 11". The accepted values are the same.
