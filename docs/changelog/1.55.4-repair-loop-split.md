# 1.55.4: project-ids repair loop split into stop check and pass

Refactor release. No output, exit code or request changes.

- `ProjectIdsRepairCommands.RunRepairLoopAsync` shrinks from 83 lines to 19. `TryStopAsync`
  decides whether the loop ends (settled, stuck, or the bound reached with or without census
  growth) and writes its closing lines. `RunPassAsync` commits one request, waits one poll and
  reaps the re-derived census.
- The five loose loop variables (previous signature, moved count, growth flag, latest total, pass
  plan) are now one `RepairPass` record per pass. The latest census total is read off the current
  report instead of being tracked separately.
- New loop transcript tests pin every line of four multi-pass runs, including one where a new
  loser id appears mid-run. In that run, moved rows must still count against the plan the pass
  committed for.
