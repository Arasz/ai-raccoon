# 1.60.1: the project id repair counts open workspaces

Bug fix. `repair project-ids` counted every workspace row as live scratch, so a project id whose
workspaces had all closed was pinned with "owns 14 open workspace(s)" and never folded. Its
committed rows stayed under the alias spelling, which the read path folds away, so `memory_get`
could not reach them under either spelling.

A workspace counts as open only while its status is neither `Closed` nor `Discarded`, and the pin
reason now names the open workspaces and the live scratch rows it really holds. An open workspace
still blocks the fold, and workspace rows still never move between projects.

Run `ai-raccoon repair project-ids --apply` once with the updated tool to fold the ids this
pinned. Their committed rows move to the canonical project id and become reachable again.

The how-to for the repair now says which workspaces hold an id back: an open one does, a closed
or discarded one does not.
