# 1.57.3: an inconclusive probe says why no backend was started

Fix release. No exit code, tool schema or settings changes. It carries the review
follow-ups from 1.57.2.

- When the launcher's probe of the port is inconclusive (a timeout, a reset, or a foreign
  answer), the exit-63 failure now says so: `the probe of port <n> was inconclusive
  (Unanswered); startup requires confirmed connection refusal`. Before, that path could end at
  `serve exit none` with no reason attached. No backend is started on this path either way,
  matching [ADR-0128](../adr/0128-refuse-unproven-backend-without-private-fallback.md).
- Debug log event 634 now reads `backend answering at <url> (identity proof pending)` where it
  read `backend live at <url>`. "Live" claimed more than the launcher knows: identity is proven
  afterwards, by the caller.
- The CLI reference's exit-code table keeps the note that `60` and `63` name the same condition
  on different surfaces below the table, where it does not split the rows.
- Test-side only: the hanging-holder contract expects ADR-0128's refusal again, and the affected
  suites carry their retry attributes.
