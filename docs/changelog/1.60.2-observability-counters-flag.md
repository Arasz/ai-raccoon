# 1.60.2: `serve observability counters` now names every registered meter

The `ai-raccoon serve observability counters` verb prints a ready-to-run `dotnet-counters` command. Before this release, the printed line (`dotnet-counters monitor -p <pid>`) carried no `--counters` argument, so `dotnet-counters` only showed the default `System.Runtime` counters (GC, CPU, working set, thread pool). None of the server's own instruments appeared, even while the server was actively handling MCP tool calls.

After this change, the printed command names every meter the server registers:

```bash
dotnet-counters monitor -p <pid> --counters AiRaccoon.MemoryTools,AiRaccoon.PromotionQueue,AiRaccoon.Background,System.Runtime,System.Net.Http
```

A user of the installed tool sees the five meters in one session: the three AiRaccoon meters (tool invocations split by `project_id`, background passes, promotion-queue state), the .NET runtime counters the bare command already gave, and HTTP. A provider with no measurements in the window produces no rows instead of an error, so the list stays safe even when a meter is quiet.

The `counters`, `trace`, `otlp` and `pid` kinds of `serve observability` keep the same four failure exit codes (`61` nothing listening, `56` server too old, `58` OTLP off, `41` foreign listener) documented in the CLI reference. The server's instrumentation itself does not change; only the command the CLI pastes does.
