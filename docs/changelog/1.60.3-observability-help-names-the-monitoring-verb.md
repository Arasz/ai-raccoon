# 1.60.3: the root help points at the monitoring command

`ai-raccoon --help` listed `serve` and never mentioned that `serve observability`
exists, so the command that prints a ready-to-run monitoring command for a running
server was only findable by already knowing it. The `serve` entry now names it, and
the CLI reference's top-level verb row does the same.

`ai-raccoon serve observability --help` has named what each kind prints (counters,
trace, otlp, pid) since 1.60.2. A test now pins the kind-to-yield pairing on both
help surfaces, so a later edit cannot quietly swap one kind's output for another's.

Ships in PR #899.
