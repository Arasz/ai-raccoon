# 1.56.1: long queries no longer time out in keyword search

Fix release. No exit code or tool schema changes.

- `memory_search` and code search cap a long query's keyword (FTS) terms. A query over 64 words
  now searches its first 64 distinct words, with stopwords and repeats dropped. That includes the OR
  fallback of a query with only a few content words in a long run of filler. A 7,259-character
  query used to OR 968 terms and took 74 s on a 22,450-entry bank; it now takes about 0.3 s, so
  clients stop cancelling it. Queries of 64 words or fewer are searched exactly as before.
- Long-query rankings change: a word repeated in a pasted query no longer counts extra, and words
  after the 64th distinct one are not keyword-searched. The long-query warning now says so instead
  of "Keyword (FTS) matching still searches the query in full."
