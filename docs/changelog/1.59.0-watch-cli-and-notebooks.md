# 1.59.0: register watches from a terminal; notebooks are indexed; skipped files are reported

Feature release. Ships #870. `memory_watch_status` gains two fields; no tool is added or removed.
The bank schema moves to v18.

- `ai-raccoon watch add <project-id> <path>`, `watch remove <project-id> <path>` and
  `watch status [project-id]` register, remove and inspect watches through the running server, so a
  machine or project can be set up from a terminal alone. They run the same checks as
  `memory_watch_add`, `memory_watch_remove` and `memory_watch_status`, which include the
  unregistered-project refusal. A refusal names the command that fixes it
  (`settings watch enable …`, `settings ingest scope add …`). An unregistered or retired project
  exits `18` and the other refusals exit `10`.
- Jupyter notebooks (`.ipynb`) are indexed into memory. Each code and markdown cell is chunked
  under a `cell N (code|markdown)` heading. Outputs, attachments and embedded images are left out,
  and a notebook that does not parse produces no rows.
- The watcher now reports the files it skips. `memory_watch_status` returns `skippedCount` and up to
  20 `skipped` entries (path and reason: `unsupported-type`, `binary`, `unparseable`).
  `watch status` prints the same list. A skipped file is no longer fingerprinted, so it is retried
  on every catch-up, and it leaves the list once it is indexed, deleted or excluded. Hidden and
  ignored files are still skipped silently.
- Schema v18 runs once and drops every watch fingerprint that has no memory or code rows behind it.
  Notebooks that 1.58.x fingerprinted without indexing are then indexed on the next catch-up,
  with no change to the file needed.
