# 1.53.9: `repair chunk-index` keeps chunks an older chunker cut

Fix release.

- `ai-raccoon repair chunk-index` no longer marks a chunk's position unknown just because an older
  version of the chunker cut it. Most chunks on a bank with any history were cut that way. Their
  stored positions came from the file in document order, so the repair now keeps them, as long as
  each chunk's text still sits in the file where its position puts it. On the author's bank the dry
  run's count of chunks it would mark unknown fell from 23,459 to 742, and chunks it would move from
  2,797 to 21 (#794, #795).
- A chunk whose text left the file, moved to another part of it, or survives only as a copy
  somewhere else is still marked unknown, on its own. Its neighbours keep their positions (#795).
- Files saved with Windows (`\r\n`) or old Mac (`\r`) line endings are read the way the chunker
  reads them, so their chunks are not mistaken for text that left the file (#794, #795).
- The repair searches each file once for all of its chunks instead of once per chunk, so a large
  file with thousands of chunks no longer multiplies the time the dry run takes (#795).
- `repair reingest` is unchanged. It still re-chunks every file that has a chunk the current chunker
  does not produce, so use it when you want every chunk cut the current way.
