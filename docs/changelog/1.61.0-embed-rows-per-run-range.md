# 1.61.0: the embed drain's rows-per-run runs from 64 to 4096, and what that value costs

The embed drain — the single consumer that turns pending rows into embeddings for both the
memory and the code corpus — takes one signal and drains a bounded number of rows per pass.
That bound has been settable since WP11-C (`ai-raccoon settings maintenance embed-rows-per-run
{rows}`), but the accepted range was "any positive integer, at most 4096", so a value of 1 was
legal.

The range is now **64 to 4096**, default still 128 — the ceiling is unchanged, the floor is
new — and the mechanics are written down for the first time ([ADR-0136](../adr/0136-the-embed-drain-rows-per-run-runs-from-64-to-4096.md)):

- **The floor (64)** is two of the embedder's 32-row sub-batches. A drain pass that reaches its
  budget re-signals itself, and every pass opens the bank, reads the setting and opens a
  telemetry span before it embeds anything — below 64 rows a pass does at most one generator
  call, so that fixed cost stops being amortised over the work.
- **The ceiling (4096)** is unchanged and still bounds the one-shot materialisation: the drain
  takes its whole `SELECT … LIMIT` result as a single list before sub-batching it, which is
  about 19 MB of managed memory for the memory corpus at the measured row size (2 325.6 UTF-8
  bytes per row on the live bank; .NET strings are UTF-16).

The value is a **pass-size** knob, not a throughput knob. The row is the unit of work: the
per-row embedding cost, the native ONNX peak and the transaction scope per row are all
unchanged by it. What it changes is how many passes a backlog takes (39 passes for 4 914 rows
at the default 128, 2 at the ceiling) and how much is held in memory at once (~0.6 MB at the
default, ~19 MB at the ceiling).

The default is unchanged, so a bank that never set the value behaves exactly as before. A value
outside the range is invalid: the CLI refuses to write it, and a value already in the settings
table is clamped to the nearest bound by the drain, which warns once per distinct bad value
(event id 1006) instead of silently using it.

```bash
ai-raccoon settings maintenance embed-rows-per-run 512   # 64..4096
ai-raccoon settings maintenance list                     # shows the effective value
```
