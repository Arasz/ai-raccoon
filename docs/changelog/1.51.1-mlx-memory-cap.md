# 1.51.1: the MLX path stops filling the machine's memory

Fix-only release, shipped by PR #744. Decision: [ADR-0114](../adr/0114-mlx-length-buckets-and-a-capped-buffer-cache.md).

- With `ai-raccoon settings model device mlx`, the server's memory footprint could grow toward the
  machine's RAM during a re-embed (17.9 GB measured on a 24 GB M4). MLX kept freed buffers for
  every distinct row length it had run. RSS never showed it; Activity Monitor's Memory column did.
- MLX sessions now pad each row to the next multiple of 64 tokens and cap MLX's buffer cache at
  512 MiB. The measured peak is about 1.2 GB, with the same per-row latency and about 7 ms more CPU
  per row. The server logs `MLX buffer cache capped at 512 MiB (was … MiB)` once per session, or a
  warning if the cap could not be set.
- Vectors are unchanged, so no bank re-embeds. Other devices (`auto`, `gpu`, `cpu`, `cuda`) are
  unaffected.
