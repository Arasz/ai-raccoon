# 1.58.0: the 1Password CLI can key the bank

Feature release. Ships #866. No tool schema changes.

- `ai-raccoon encryption 1password` makes an SSH Key item in 1Password the bank's key source, next to
  Bitwarden. It prompts for an `op://<vault>/<item>/private key?ssh-format=openssh` reference
  (`AIRACCOON_1PASSWORD_REFERENCE` sets the default), reads the ed25519 key with `op read`, and runs the
  same derivation, sidecar and rekey flow as `encryption bitwarden`. A reference that does not start
  with `op://` is refused with exit code `10` before `op` runs. `encryption show` prints the source and
  the reference.
- `op` authenticates through the inherited `OP_SERVICE_ACCOUNT_TOKEN` (headless; service accounts cannot
  read the Personal or Private vaults) or the 1Password desktop app, and `OP_ACCOUNT` picks among several
  accounts. There is no `-t` option, because a token on the command line is visible through `ps`. Rotating
  the key in 1Password means rekeying together, by running the command again.
- Exit codes `23`, `24` and `25` now cover either CLI. The code names changed from `Key.Bws*` to
  `Key.SecretCli*` (`SecretCliNotInstalled`, `SecretCliTimedOut`, `SecretCliFailed`); the numbers are
  unchanged.
- The `op` install hint points at https://www.1password.dev/cli.
