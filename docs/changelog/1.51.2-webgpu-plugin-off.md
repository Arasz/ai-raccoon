# 1.51.2: Windows and Linux stop crashing on the first embed

Fix-only release, shipped by PR #747. Decision: [ADR-0112 amendment](../adr/0112-webgpu-plugin-off-macos-and-opt-in-cuda.md#amendment-2026-09-25-the-webgpu-plugin-is-disabled).

- In 1.51.0 and 1.51.1, on a Windows or Linux machine where the packaged WebGPU plugin found a GPU,
  the server aborted on the first embed. The cause is an ONNX Runtime 1.30 bug in plugin execution
  providers ([onnxruntime#28329](https://github.com/microsoft/onnxruntime/issues/28329)). An abort
  cannot be caught, so the CPU fallback never ran. Measured on Linux (x64, Vulkan); Windows goes
  through the same ONNX Runtime code path.
- The WebGPU plugin is no longer tried on Windows or Linux. Sessions there run on the CPU, as they
  did before 1.51.0, and log `CPU (GPU refused: the WebGPU plugin aborts the process on its first
  run …)`. macOS is unaffected.
- The opt-in `cuda` device is unchanged but probably hits the same bug. If the server dies on the
  first embed after `ai-raccoon settings model device cuda <path>`, switch back with
  `ai-raccoon settings model device auto`.
- CPU vectors are what the bank already holds on these hosts, so nothing re-embeds.
