# 2.5.0: a watcher overflow logs once and rescans; the buffer size is a setting

## New

When a burst of file changes fills a watch's event buffer, the watcher drops events. The server now
collects the overflows of one watch for two seconds, writes a single warning with their count
(event 304), and queues one changed-files scan for that watch. Before, each overflow wrote two error
lines (events 300 and 330) and no scan ran until the next 5-minute heal.

The buffer size is now the global setting `watch.buffer-size.global`, in bytes. It defaults to 65536 and
is clamped to 4096–65536. A new value applies to watchers started after it is written. The setting only
matters on Windows; other platforms ignore the buffer.

## Not in this release

Watching only the allowed directories, instead of a recursive watch that includes ignored folders, is
left open; the reasoning is in [ADR-0143](../adr/0143-watcher-overflow-is-one-debounced-rescan.md).
