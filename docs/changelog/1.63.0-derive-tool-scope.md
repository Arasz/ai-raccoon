# 1.63.0: The reserved shared target refuses a delete, and a new MCP tool must say where it may run

The built-in `shared` document target, introduced in 1.62.0, now refuses `memory_delete`. Its
content belongs to its watch and to the file on disk: a delete there removed only the chunk whose
hash was named, advanced no watch fingerprint, and left the watch digest hash-skipping on a file
it still claimed was current — a partial delete nothing reconciled. Delete the file, or remove
the watch.

Which tools the reserved target accepts is now declared on the tools themselves. Every MCP tool
carries a scope — `All` (any target), `Shared` (the reserved target only) or `Project` (an
ordinary project only) — and the build fails if a tool declares no scope. Adding a tool to the
MCP surface can no longer reach the reserved target by omission: the decision is written next to
the tool, and the compiler asks for it. A tool name that is not a declared tool is refused there,
where the old list allowed anything it did not name.

Nothing else changes for a caller: the tool set, the wire shapes, the refusal messages and the
gate's order of checks are the same — the same fourteen tools are ordinary-only and the same
sixteen may use the reserved target. ADR-0139 records the decision; ADR-0137 is amended with
the reserved target's refusal list.
