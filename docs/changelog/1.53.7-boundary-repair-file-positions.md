# 1.53.7: file chunk positions repair themselves, and repair reports stop timing out

Fix release.

- Some indexed files held two chunks at the same position, which could pair the wrong chunks when
  search pulls in a hit's neighbours. Nothing corrected them on its own. The chunk-boundary repair
  now finds them and gives each chunk its real position in the file, keeping the chunks and their
  embeddings (#788).
- Files the chunker has to cut mid-term, such as whitespace-free JSON, were re-ingested by that
  repair every time it ran and reported as repaired. It now sees that a re-ingest would write the
  same chunks and leaves them alone.
- A file that repeats a chunk word for word now numbers its chunks without gaps, and its chunk
  count is the number of chunks actually stored, the same way every other path counts them. Before,
  a repeated chunk left a hole in the numbering, so search's neighbour boost missed the chunk next to
  it.
- `ai-raccoon repair chunk-index` (and `repair reingest`, and the project-id census) no longer gives
  up after 100 seconds on a large bank with "no settings server answered". A report now runs until
  the server answers or you press Ctrl-C; other settings commands still fail after 100 seconds when
  the server stops answering.
- Existing banks run the repair once more on the first maintenance pass after this upgrade, with no
  manual step.
