# 1.57.4: the file watcher's event buffer is 64 KB

Fix release. No tool schema or settings changes.

- On Windows, each file watcher now uses a 64 KB internal buffer instead of the 8 KB default. A
  burst of changes under a watched directory (a `git checkout`, an IDE "reformat all", an install)
  could fill 8 KB faster than it drained; the OS then raised `InternalBufferOverflowException`
  (logged as events 300 and 330) and dropped every event it could not store. 64 KB is the
  documented maximum for `FileSystemWatcher.InternalBufferSize`, so this is the largest headroom
  the property allows. A burst larger than 64 KB can still overflow, and the 5-minute catch-up
  scan remains the backstop.
  [ADR-0129](../adr/0129-file-watcher-event-buffer-is-64-kb.md)
