# 1.55.5: `doctor` handler split into named steps

Refactor release. No output or exit code changes.

- `DoctorCommands.RunAsync` shrinks from 63 lines to 36. It now reads as the command's steps:
  check the bank exists, resolve the key, open the bank read-only, diagnose the schema, then read
  and report. `TryResolveKeyAsync` and `TryOpenAsync` each own their failure reporting, and
  `ReadAndReportAsync` gathers the engine, threads, migration and Core ML state.
- A new doctor test covers the one `RunAsync` branch no test reached before: a bank the read-only
  open cannot open exits `OpenFailed` and says so on stderr. It skips when run as root.
