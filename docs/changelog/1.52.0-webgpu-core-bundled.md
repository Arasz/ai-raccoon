# 1.52.0: WebGPU on Windows and Linux x64 again, from a bundled core

Feature release. Decision: [ADR-0115](../adr/0115-bundle-onnxruntimes-webgpu-core-for-windows-and-linux-x64.md).

- The win-x64, win-arm64 and linux-x64 packages ship ONNX Runtime's own WebGPU-enabled core (the
  `onnxruntime-node` 1.30.0 build, same release and commit as the managed package) under `webgpu/`.
  The tool loads it instead of the NuGet core, so the bundled engine runs on the GPU under `auto`
  again. It replaces the WebGPU plugin that 1.51.2 turned off after it aborted the process on its
  first run.
- Measured on Linux x64 with a software Vulkan driver (vectors match the CPU at cosine > 0.999, no
  abort). A real GPU on Linux and D3D12 on Windows are not measured yet. Linux needs the Vulkan
  loader (`libvulkan.so.1`) and a Vulkan driver; without one the session falls back to the CPU and
  says why.
- linux-arm64 and linux-musl-x64 have no WebGPU build and stay on the CPU. Their execution provider
  line reads `CPU (GPU refused: this platform's ONNX Runtime core has no WebGPU)`.
- The opt-in `cuda` device is unchanged and still unverified. It goes through the plugin mechanism
  of the upstream bug and may abort the same way; `ai-raccoon settings model device auto` undoes it.
- A bank embedded on the CPU keeps its vectors. The GPU's match them (cosine > 0.999), so nothing
  re-embeds.
