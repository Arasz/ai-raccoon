# 1.55.2: one owner-only secret file class

Refactor release.

- `IdentityKeyFile` and `McpTokenFile` now derive from one base class, `OwnerOnlySecretFile<T>`.
  The ensure path (process gate, cross-process lock file, refusal handling), the read-or-mint
  loop, the heal-window debris delete and the exclusive 0600 create are written once instead of
  twice. Each file keeps only what is its own: the key file its P-256 mint, parse and signer
  cache, and the token file its Base64Url mint and the project root's legacy token adoption.
- The two classes keep their public surface: `FileName`, `HealAfter`, the constructors, `Path`,
  `StateDirectory`, `EnsureAsync`, `Read`, `ReadKeyId` and the refusal flags.
- A mint whose exclusive create loses, or whose write is cancelled, now always disposes the key it
  generated.
- A token read that finds a readable file now clears a refusal left by an earlier read in the same
  ensure, as the key file already did.
- A new race test pass (`SecretFileRaceTests`) covers racing key mints and heals, a key file that
  fills in during the heal wait, racing legacy token adoptions, the lock file holding off a
  concurrent ensure, the heal delete sparing a valid aged secret, and the key and token ensured
  together in one state directory.
