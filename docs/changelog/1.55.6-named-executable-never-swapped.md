# 1.55.6: a named backend executable is never silently replaced

Fix release. No exit code changes; the failure the launcher already reported returns for one case
that had quietly started another program instead.

- The 1.52.2 rescue (the proxy's own executable was deleted by `dotnet tool update -g ai-raccoon`,
  so the global-tool shim or `PATH` supplies the replacement) now applies only to the process's own
  executable. An explicitly named executable that no longer exists fails to start exactly as named
  — `could not start` — instead of silently spawning whichever `ai-raccoon` the shim or `PATH`
  happens to offer on the machine.

## Also shipped in 1.55.6: the duplication-review refactor series

These merged after 1.55.5 and went out in this release without their own entries; they are recorded
here. Most are refactors with no output or exit code changes; the behaviour changes are named.

- **Writes roll back when cancelled** (#814). 28 hand-written `BEGIN IMMEDIATE` / `COMMIT` /
  `ROLLBACK` blocks now share `WriteTransaction.InWriteTransactionAsync`, which rolls back with an
  uncancellable token; most old copies skipped the rollback on cancel and left the transaction open
  on the pooled connection. The two replace-path transactions in `SqliteMemoryStore.Replace.cs`
  still rolled back with the caller's token in this release. The chunkers share `TextLines`.
- **Owner-only secret files** (#815). The identity key and the MCP token share
  `OwnerOnlySecretFile<T>`. A mint whose create loses, or whose write is cancelled, now always
  disposes the key it generated; a token read that finds a readable file clears a refusal left by
  an earlier read in the same ensure.
- **Settings reads and SQL commands** (#826). Settings reads go through one connection-level
  reader and SQL command definitions come from one factory. Fix: two queries (project ids, shared
  index) received the cancellation token as their parameters object, so cancelling them did nothing.
- **Handlers split into named steps, no output changes**: `repair project-ids` (#816, which also
  stops counting queue-only changes twice; #817; #829), `serve --restart` (#819), `serve` start
  (#820).
- **Shared skeletons, no output changes**: cloud-store ETag and error mapping (#823), the integer
  setters and the `chunk-index`/`reingest` repair commands (#824), and the hosted services' pass
  wrapper, tick loop and interval read (#825).
- **Tests and CI**: shared test fakes and setup (#827, #828), and a CI gate that fails when exact
  duplication in `src/` reaches 1% (#822).
