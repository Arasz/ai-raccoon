# 1.53.5: a long note that cites a file keeps its chunks in order

Fix release.

- A long `memory_write` note written with a source file used to store its first chunk last, so
  its opening got the highest chunk position and `memory_search` reported it as the note's last
  chunk. Notes are now stored in text order, and the opening is chunk 0.
- Existing banks repair themselves once, on the first maintenance pass after the upgrade. Each
  note's order is checked against the note's own content hash before anything moves; a note whose
  order cannot be proven is left as it is and counted in the log (event 446). A sync no longer
  puts notes back out of order.
- The chunk-boundary repair from 1.53.3 now uses the same check. A note stored in text order (one
  split by the old chunk backfill, for example) is repaired in that order instead of having its
  last row read as its first (ADR-0122, #779).
