# 2.0.1: a call to a tool this server does not have is answered with the tool to call

2.0.0 renamed every MCP tool and shipped no aliases. A client that still spoke the old names
got the SDK's own answer — a JSON-RPC `-32602` reading `Unknown tool: 'memory_search'` — which
tells the caller that the tool does not exist and nothing else. It does not say that the tool was
renamed, and it does not say what to call instead.

Such a call is now a normal tool error, in the place the MCP protocol says a model can read it
and act on it:

```
unknown-tool: 'memory_search' was renamed to 'query' in 2.0.0 — call 'query' instead.
```

A name the rename did not take gets the general message:

```
unknown-tool: 'no_such_tool' is not a tool on this server. This server exposes 30 tools; call tools/list to see them.
```

Nothing else changes: the tool set, the wire shapes and every other refusal message are the
same, and the old names stay dead — this is an answer, not an alias. The refusal is logged like
every other expected failure, at `Information` rather than `Error`: a client naming a tool that
does not exist is the client's mistake, not a server fault.

**If your client was connected across the 2.0.0 upgrade, reconnect it.** A connected client
keeps the tool list it fetched, so its catalogue holds thirty dead names and the new ones are not
callable from that session at all. The answer above makes the next call recoverable; a
reconnect is what makes the new names callable.

ADR-0140 records the decision.
