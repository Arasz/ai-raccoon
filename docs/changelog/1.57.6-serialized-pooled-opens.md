# 1.57.6: concurrent bank opens no longer share a pooled connection

Fix release. Ships #861. No tool schema or settings changes.

- Every pooled SQLite open now takes its pool checkout under one process-wide lock. Microsoft.Data.Sqlite
  10.0.12 can lend the same native connection to two opens that run at once. When both close it, the
  pool keeps it twice, and its idle pruning later disposes a copy that is still pooled or in use. The
  next open then fails on its first statement with
  `ObjectDisposedException: ... Object name: 'SQLitePCL.sqlite3'`, which showed up as
  `Watch re-watch reconcile pass failed`. Two writers can also end up on one connection
  (`cannot start a transaction within a transaction`). The lock covers only the checkout, so pragmas,
  schema work and queries still run concurrently. It comes out once a Microsoft.Data.Sqlite release with
  the upstream fix (dotnet/efcore#39012) is pinned.
- A bank open whose pragma fails (a cancellation, a busy bank) now closes its connection instead of
  leaving it checked out of the pool.
