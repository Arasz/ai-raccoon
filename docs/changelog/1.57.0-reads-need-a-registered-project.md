# 1.57.0: reads need a registered project id too

Minor release with one breaking change. It adds two exit codes (18, 19), three CLI verbs, and one MCP tool. PR #846.

- **Breaking: every call refuses an unregistered or retired project id, reads included.** `memory_search`, `memory_get`, `memory_list`, `memory_stats`, `code_get`, `memory_performance`, `memory_watch_status`, `memory_workspace_status`, `memory_promotion_list`, `memory_sweep` dry runs and `memory_share_extract` propose now return `project-not-registered` or `project-retired` instead of empty results.
  - A refused call leaves no `metrics` or `search_quality` row under the refused id. On the owner's bank, 12 phantom ids had collected that way.
  - A legacy id the bank already holds rows for keeps working, with warning 433.
  - Calls that need no registered id:
    - `project_id_token_get`
    - `project_id_get`
    - `memory_promotion_list allProjects=true`
    - `memory_performance` under `__self_metrics__`
  - [ADR-0127](../adr/0127-reads-need-a-registered-project-id.md)
- **Registering an id a project already uses.**
  - `ai-raccoon project id register <id> [--name <n>]` registers it. An alias of a registered project answers `already registered <winner>`, and a retired id exits 18.
  - `project id get --name <n>` prints the id registered under a name. It exits 18 when nothing is found and 19 when the name is ambiguous.
  - `project id check <id>` prints `known`, `unknown` or `retired`.
  - MCP `project_id_get(name)` looks an id up before `project_id_token_get` mints a new one.
- **Settings writes keyed by a project id check it too.** This covers `settings access set`, `settings watch enable|disable`, `settings watch concurrency` and `settings ingest scope add`.
  - An alias is written under its winner.
  - An unknown or retired id exits 18.
  - Removing paths from a scope, and the DELETE-backed removals, still work under any id.
  - A raw-text id that is neither registered nor holding rows (for example `ai-badger` before its first memory write) can no longer add a scope or enable a watch until you register it with `ai-raccoon project id register <id>`. Ids that already hold rows keep working.
- **ToolGate resolves aliases with or without a finished repair.** Reads under an alias id no longer fail while a project-ids repair request is open.
- **`repair project-ids --apply` waits for the server to stamp the request finished before it reports a result.** Before, it could print `pinned-only … P3 armed` with stale alias counts about 3 minutes early. If the server has not finished when the time budget runs out, it now exits 37.
- **The repair census counts `search_quality` rows as telemetry.** An unregistered id that owns only telemetry is now pinned instead of being listed for a human to attribute.
- **Search-quality records are scoped to their project.** `memory_record_grade` and `memory_record_followthrough` update only a record that belongs to the caller's project. `recorded` is now false when no row matched, instead of always true.
- Warning 433 no longer points at the `project id convert` command, which never existed.
- Not covered yet: `memory_sync` pull and watches created before 1.57.0 still store rows under ids nobody registered ([#847](https://github.com/Arasz/ai-raccoon/issues/847)).
