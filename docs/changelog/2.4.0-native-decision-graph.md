# 2.4.0: AiRaccoon keeps the project's decisions

## New

Decisions are now records in the bank, not notes. Each has versions, a status (`proposed`, `accepted`,
`rejected`, `superseded`, `deprecated`), typed links to other decisions and the task that recorded it.
Thirteen MCP tools cover the work: `register_decision_task`, `record_decision`, `amend_decision`,
`transition_decision`, `supersede_decision`, `link_decisions`, `unlink_decisions`, `get_decision`,
`query_decisions`, `find_decision_precedents`, `get_decision_graph`, `export_decisions` and
`preview_decisions`. The server now has 43 tools. Every decision tool requires `projectId`, and
writes carry a `sessionId`/`requestId` pair, so a retry replays the first answer instead of
writing twice.

`ai-raccoon decisions` does the same from a terminal through the running server: `task register`,
`record`, `get`, `query`, `export` and `preview`. Export and preview take the latest registered task
by default, `--tasks <n>` the last `n`, and `--all` every task. `decisions export` has no size cap;
over MCP, `export_decisions` refuses anything over 1 MiB and names the command to run instead.

The project's access mode applies to all of it: in `ro` a decision write is refused as
`access-denied` over HTTP and MCP, and the CLI exits 17.

A field a decision request does not define is refused as `invalid-argument` over HTTP and MCP, and
`decisions record` exits 10, so a misspelled field is never silently dropped.

`repair project-ids` holds back an id that owns decisions instead of folding or retiring it, and the
held-back id keeps its own identity, so its decisions stay reachable.

## Upgrade and rollback

**Back up the data root before upgrading. 2.4.0 migrates the bank to schema v23, and 2.3.0 refuses to
open it.** There is no downgrade migration. To roll back, stop every `ai-raccoon` process, restore the
backup and install 2.3.0; decisions and memory written since the upgrade are lost, so export the
decisions first if you need them. The steps are in the
[how-to](../how-to/record-project-decisions.md#upgrade-and-roll-back).

Decision tables are not part of cloud sync. Keep your Semantica configuration: importing Semantica
exports is not in this release (#924), and agent instructions switch to the native tools in a
separate change.
