# 1.55.1: one shared write transaction, one shared line splitter

Refactor release.

- Every bank writer that wrapped its work in `BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK` by hand now
  calls one helper, `WriteTransaction.InWriteTransactionAsync`. It replaces 28 hand-written copies
  across the schema migrations, the repair jobs, the chunk-budget reconciler, the embedder, the watch store and the memory store,
  including two private copies of the same helper under different names.
- A cancelled write now always rolls back. Most of the old copies sent `ROLLBACK` with the
  cancelled token, which skipped it and left the transaction open on the connection. Three copies
  already used an uncancellable rollback, and the helper now does the same everywhere.
- The Markdown and code chunkers share `TextLines.Split` and `TextLines.NormalizeLineEndings`
  instead of carrying identical private copies.
- The two replace-path transactions in `SqliteMemoryStore.Replace.cs` keep their own wrapper,
  because they time the lock wait and hold between `BEGIN` and `COMMIT`.
  Those two still send `ROLLBACK` with the caller's token, so a write cancelled mid-flight there
  can still leave its transaction open on the connection; fixing them while keeping the timings is
  a follow-up.
