# 2.10.2: a skipped file is no longer re-ingested on every watch pass

A fix. No schema change.

- **A watched file that ingest skips is no longer read, hashed and replaced on every pass.** A file with an indexed
  extension whose content ingest refuses (binary bytes, unparseable content, code that gives zero chunks) lost its
  watch fingerprint on each replace. Catch-up then saw it as new on every pass, ran the replace again and logged
  EventId 899 (`0 row(s) written`) at Information each time. The replace now keeps a skip-marked stamp: an
  unchanged file is not due, a changed file is retried, and the marker never hash-skips a real ingest. The
  first catch-up after a server start retries each skipped file once, so `get_watch_status` still lists it.
