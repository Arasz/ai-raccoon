# 1.51.3: the server notices its own install disappearing and exits

Fix-only release, shipped by PR #752. Decision: [ADR-0116](../adr/0116-server-exits-when-its-install-is-replaced.md).

- `dotnet tool update -g ai-raccoon` deletes the running backend's install directory while it is
  still serving. Until now the process stayed up regardless, and `ModelMigrationJob`/`CodeReindexJob`
  logged a warning on every maintenance poll, forever, until someone ran `serve --restart` by hand.
- The server now notices its own install directory is gone within 20 seconds and shuts itself down
  cleanly, logging one warning first. The next MCP call's proxy forward starts the new install —
  `dotnet tool update -g ai-raccoon` alone is a complete recovery.
- The startup log line now names the running version and its install directory, so it can be matched
  against the shutdown warning above.
