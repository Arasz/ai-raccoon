# 2.0.0: the MCP tool surface is renamed

Every MCP tool has a new name. This is a **breaking change with no aliases**: the old names are
gone, and a client that still calls them gets nothing. `memory_search` is now `query`,
`memory_get` and `code_get` are one `get_entry`, `memory_write` is `add_memory`, and so on
across the whole surface — 30 tools, one name each.

**The old → new map**

| old | new |
|---|---|
| `memory_search` | `query` |
| `memory_get`, `code_get` | `get_entry` |
| `memory_list` | `get_index` |
| `memory_stats` | `get_store_statistics` |
| `memory_performance` | `get_engine_statistics` |
| `memory_record_followthrough` | `set_memory_usage_record` |
| `memory_record_grade` | `set_query_result_grade` |
| `memory_write` | `add_memory` |
| `memory_ingest_file`, `memory_ingest_directory` | `ingest_file`, `ingest_directory` |
| `memory_delete`, `memory_delete_context` | `delete_entry`, `delete_context` |
| `memory_share` | `share_memory` |
| `memory_share_extract` | `trigger_memory_sharing` |
| `memory_promotion_list`, `memory_promotion_discard` | `get_memories_sharing_ranking`, `delete_memory_from_ranking` |
| `memory_sweep` | `trigger_memory_cleanup` |
| `memory_set_ttl` | `set_memory_ttl` |
| `memory_workspace_begin`, `_status`, `_consolidate`, `_discard` | `initialize_workspace`, `get_workspace_status`, `close_workspace`, `discard_workspace` |
| `memory_watch_add`, `_status`, `_remove` | `add_watch`, `get_watch_status`, `remove_watch` |
| `memory_sync` | `sync_to_cloud` |
| `memory_embed_pending` | `embed_deferred_entries` |
| `project_id_get`, `project_id_token_get` | `get_project_id`, `save_project_id_token` |

**What else changed**

- **`get_entry` is one tool.** It used to be two — `memory_get` and `code_get` — over two
  corpora. It now reads whichever corpus owns the hash and returns one shape
  (`{hash, value, path, context?, createdAt?, lineStart?, lineEnd?, entryType}`). A hash that
  two corpora hold — the same bytes as a note and as a code file — is refused rather than
  guessed. The tool declares the `All` scope: a memory entry can live in the reserved `shared`
  target, a code chunk cannot, and the entry type decides which corpus a call reaches.
- **A new read tool, `get_quality_report`.** The quality surface had two writers and no
  reader: `set_query_result_grade` records the usefulness grade, `set_memory_usage_record`
  records the follow-through, and `get_quality_report` reports what the server knows about past
  queries — total searches, follow-through searches, graded searches, average grade, coverage,
  searches per day, over a window that defaults to the last seven days.
- **`close_workspace` promotes on close.** Closing a workspace promotes the kept hashes into the
  project; `discard_workspace` drops it.
- **The MCP prompt text, the CLI help and the SQL comments name the new tools.** A prompt that
  told an agent to call `memory_search` would have called a tool that no longer exists.
- **The scope model is unchanged in shape.** Every tool still declares the scope it may run
  against (ADR-0139), and the reserved `shared` target still refuses the same ordinary-only
  tools (ADR-0137). `get_entry` is the one tool that moved from ordinary-only to any-target,
  because it now reads the memory corpus too.

**A fix that came with it.** The reserved `shared` target owned the literal *id* but not the
literal *name*: `save_project_id_token {name: "shared"}` minted a private project under it, and
name lookup then answered with the reserved id for ever — leaving that project unreachable by
name and letting the target publish over rows ADR-0137 says must block it. The mint tool now
refuses the reserved name, and the activation guard also keys on the name, so a bank that already
holds such a row blocks the target instead.

**What a client has to do**

Rename the calls. There is no compatibility window and no alias: the framework that ships with
ai-badger 0.214.0 speaks the new names, and it must be updated before this release is
installed (`https://github.com/Arasz/ai-badger/pull/650`).
