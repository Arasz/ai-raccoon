# 2.9.1: clearing a TTL is Memory-only

Fix release. No schema change.

- `set_memory_ttl` with no `ttlDays` on a File or unclassified entry is refused as `not-a-memory-entry`, the same as setting a TTL. From 2.2.0 to 2.9.0 it returned success. Since schema v24 such an entry cannot carry a TTL, so the success did nothing.
- Docs match the product: the `set_memory_ttl` reference and the capabilities page no longer say cleanup honours a File TTL from before 2.1.0, and the `query` reference says `get_entry` cannot read an unclassified (`none`) hit.
- The manual checks `typed-memory-only-ttl` and `typed-query-all-selections` say what the product does: clearing is refused on every non-Memory entry, and any selection that names both `memory` and `file` also returns unclassified rows.

Found by the 2.9.0 manual checklist run. [ADR-0150](../adr/0150-clearing-a-ttl-is-memory-only.md)
