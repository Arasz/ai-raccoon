# 2.6.0: Semantica decisions import into the native graph

## New

`ai-raccoon decisions import-semantica` brings a Semantica 0.7.0 `export_graph` JSON file into a project's decision graph. Without `--apply` it only previews: it reports what would be written and what blocks the import, then prints the exact apply command. Apply must name the digests of both files and the project revision the preview saw, so an import cannot run against input nobody reviewed.

You write a mapping file that gives each source record a stable ID and each decision an explicit status. The import never guesses a status from an outcome string. Records it cannot turn into decisions or edges, such as people and categories, are kept verbatim for later. Importing the same file again writes nothing.

The server gains `POST /decisions/projects/{projectId}/imports/semantica/preview` and `.../apply`. There is no new MCP tool, so the tool count stays at 43. See [Record project decisions](../how-to/record-project-decisions.md).

## Not in this release

Semantica's other export formats are not supported, and neither is the normalized nodes and edges shape, which no real exporter produces. A `superseded` decision cannot be imported directly: import both records as `accepted`, then call `supersede_decision`. Semantica 0.6.6 cannot produce an export at all, so upgrade to 0.7.0 first. Agent instructions still point at Semantica; moving them to the native tools is a separate change.
