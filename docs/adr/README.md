# adr/

Architecture decision records: immutable, frozen. Each file records one decision in date
order (`NNNN-slug.md`); records are never edited after acceptance — a new decision gets a
new number. Add an ADR for any architecture-level decision via `create-task-spec` /
`owner-gate-review` workflow.

| [0018 — Promotion scoring v2](0018-promotion-scoring-v2.md) | Replaces `SharedExtractionService`'s four additive bonuses (measured +0.125 Spearman) with `PromotionScorer`: a 14-archetype provenance prior, bounded content-shape evidence, and an organic-entry refinement layer; `CandidateFloor` recalibrated 1.0 → 0.4; recency drops from the score to a sort tie-break only |
| [0019 — Forward-version write guard](0019-forward-version-write-guard.md) | `MemorySchema.EnsureAsync` refuses a read-write open when the stored schema version is ahead of the binary's `CurrentVersion`, closing the silent-no-op path that caused issue #200's chunk-column drift; recovery is updating the binary, not a downgrade or override |
| [0020 — Always-on HTTP: the stdio entry point becomes a proxy](0020-always-on-http-stdio-proxy.md) | Bare `ai-raccoon` becomes a thin stdio→HTTP proxy that probes for `ai-raccoon serve`, starts one if absent and forwards every JSON-RPC message to it, so one process owns the bank instead of N peers; `--transport stdio` keeps the in-process server as the escape hatch; reverses the "no self-spawning daemon" position and supersedes R15/R16; ships with a loopback token on `/mcp` |
| [0021 — Export the ASP.NET request span](0021-export-the-aspnet-request-span.md) | Registers `Microsoft.AspNetCore.Hosting` so the request span is exported and tool spans nest under it, fixing every exported span being an orphan with a dangling `parent_span_id`; takes the `SuppressActivityOpenTelemetryData` AppContext switch over a fourth OTel package; tool spans stay `Internal` against the MCP convention so two nested `Server` spans do not double-count request rates; supersedes ADR-0002 §Non-Goals b2 and ADR-0009 §Non-Goals b1 and moves ADR-0002 to Superseded |
| [0022 — `serve --restart` over an authenticated loopback shutdown](0022-authenticated-loopback-restart.md) | `serve --restart` cycles the ai-raccoon server already on the port instead of attaching to it, closing the `dotnet tool update` lockout ADR-0020 left open: a token-guarded `POST /shutdown` (mapped only on a gated host, POST-only, answered before the host stops) plus a bounded wait for the port to free; `/observability` gains the binary version as the discriminator; every failure is a loud non-zero exit and `--restart` never falls back to attaching; no process is ever killed by PID |
| [0023 — Invalidate promotion_queue rows when their entry is deleted](0023-promotion-queue-entries-delete-invalidation.md) | An `AFTER DELETE ON entries` trigger (`promotion_queue_entries_ad`) drops the matching `promotion_queue` row on any entry delete, guarded by `NOT EXISTS` so a live sibling under `uq_entries_committed_bucket` keeps the candidate; no `CurrentVersion` bump — additive and idempotent; `ai-raccoon extract prune` (dry-run by default, `--apply` to delete, idempotent) catches up rows orphaned before the trigger existed |
| [0024 — Unknown ids: idempotent removal reports a count, a state transition refuses](0024-unknown-id-contract.md) | Records the rule closing three repeated "is this a bug" sweeps: `memory_delete`/`memory_delete_context`/`memory_promotion_discard`/`memory_watch_remove` are idempotent removal verbs that return `0`/no-op on an unknown id; `memory_share` and the workspace family are state transitions that refuse an unknown id with a typed exception; no behaviour change, both sides already matched the rule |
| [0025 — The sweep reaper](0025-the-sweep-reaper.md) | Retroactive ADR for the 1.6.0 default-on background reaper: on-by-default kept (pre-1.6.0 banks were already inert against it, no TTL ever set); `sweep.enabled`/`sweep.threshold` stay bank-global, not per-project; the reaper now honours a project's access mode (skips non-`full` projects) closing the gap where `memory_sweep` refused in `ro` but the timer reaped anyway; a pass that deletes something finally emits a span, a pass where every project failed finally reports a non-`success` result; the fail-open kill switch parse is kept as-is and flagged for a future call, not changed here |
| [0026 — Persistent discards and shared-value exclusion](0026-persistent-discards-and-shared-exclusion.md) | `RankAll` builds the shared-value set whitespace-stripped, exactly mirroring `PromoteAsync`, so an exact twin or a whitespace twin of an already-shared value is never proposed again |
| [0027 — Extensible file-type handlers and JSON support](0027-extensible-file-type-handlers-and-json-support.md) | Three focused `AiRaccoon.Core` interfaces replace the markdown-only ingest path, so a new file type is a handler registration rather than a change to `FileIngestor` |
| [0029 — Pre-write noise filtering](0029-pre-write-noise-filtering.md) | `INoiseFilteringService` runs inside `SqliteMemoryStore.WriteAsync`, rejecting machine-generated content before it reaches the bank; superseded in part by ADR-0033 and ADR-0039 |
| [0030 — Real-time heuristic TTL assignment](0030-realtime-heuristic-ttl.md) | An `IAutoTtlPolicy` pipeline injected into `SqliteMemoryStore` assigns a TTL at write time; reversed by ADR-0034, which found the assignment never reached the database |
| [0031 — Polly resilience pipelines](0031-polly-resilience-pipelines.md) | Polly v8 (`Polly.Core` + `Microsoft.Extensions.Http.Resilience`) standardizes every HTTP resilience policy on exponential backoff with decorrelated jitter, replacing per-client hand-rolled retries |
| [0032 — A write outcome is truthful](0032-truthful-write-outcome.md) | `MemoryEntry` gains additive `Stored`/`Reason` members rather than a new return type, so a rejected write says it was rejected instead of returning a fabricated entry that no `memory_get` could ever resolve |
| [0033 — Remove the zero-shot noise filter and noise learning](0033-remove-zero-shot-noise-filter-and-noise-learning.md) | Deletes the zero-shot filter and the learning subsystem feeding it, keeping only the deterministic `HermesProcessNoisePolicy`; superseded by ADR-0039, which restores the substrate without a scoring model |
| [0034 — An explicit TTL is authoritative](0034-explicit-ttl-is-authoritative.md) | No heuristic assigns a TTL at write time: `PromotionScorerTtlPolicy` and `IAutoTtlPolicy` are deleted as dead code that described and tested behaviour which never reached the database; reverses ADR-0030 |
| [0035 — `memory_get` and query-relevant snippets](0035-memory-get-and-query-relevant-snippets.md) | Adds `memory_get(projectId, hash)` with the same reach `BumpAccess` already grants search hits, plus query-relevant snippets and content-keyed dedup, closing the gap where no tool could retrieve an entry by hash |
| [0036 — Engine-aware chunk token budget](0036-engine-aware-chunk-token-budget.md) | Chunks are counted with the tokenizer that will actually embed them rather than a proxy, with a guaranteed split floor so no chunk is ever truncated at embed time |
| [0037 — Workspace and promotion-queue concurrency guards](0037-workspace-and-promotion-queue-concurrency-guards.md) | A partial unique index on `entries(path, hash, workspace_id)` plus a v7 migration ladder step that dedupes first; promotion claims gain a reclaim path for stale holders |
| [0038 — Cache the resolved encryption key per config fingerprint](0038-cache-the-resolved-encryption-key-per-config-fingerprint.md) | The sidecar is still read on every resolve, so a config edit is always seen; only the provider's `GetPassphraseAsync` — the step that shells out — is skipped when the fingerprint is unchanged |
| [0039 — The noise-learning substrate and shadow mode](0039-noise-learning-substrate-and-shadow-mode.md) | Supersedes ADR-0033: restores the learner-agnostic substrate and shadow mode only, ships no scoring model, and leaves a marked seam for one |
| [0040 — Read-path query guard](0040-read-path-query-guard.md) | `memory_search` gets a two-tier guard evaluated on the raw query before any other work: refuse a query that is itself machine output, annotate one that merely contains log-like content |
| [0041 — Structural/lexical noise detector](0041-structural-noise-detector.md) | A pure shape-statistics detector (no embedding) joins the read-path warn tier as a third input, default off; it can add an annotation but never a refusal |
| [0042 — Fixtures are built by the product, not beside it](0042-fixtures-are-built-by-the-product-not-beside-it.md) | Deletes the parallel Python chunker that populated a `section` column the product never wrote, and routes the corpus scripts through `memory_ingest_file`; a fixture built by a second implementation hides the first one's defects |
| [0043 — A probe with no answer is not an empty port](0043-a-probe-with-no-answer-is-not-an-empty-port.md) | `ProbeVerdict` splits a refused connection (proof the port is free) from a probe that got no answer at all; `serve --restart` may still bind on the unknown, but a refused bind now refutes the pre-check instead of reporting a lost port nothing ever took |
| [0044 — The section column's FTS weight is 4, not 16](0044-section-fts-weight.md) | `section` carried a 16x bm25 weight while `FileIngestor` wrote it as NULL for every ingested chunk, so the weight had never met real data; measured A/B on one corpus, populating the column beats leaving it NULL and weight 4 beats weight 16 (nDCG@5 0.5703 → 0.5733 → 0.5846). Records two defects it exposes but does not fix: one `expectedSource` per query in the baseline catalog, and heading extraction reading shell comments as headings when a chunk starts inside a code fence |
| [0045 — A context is a label inside a project, not a second isolation boundary](0045-context-is-a-label-not-a-boundary.md) | A `memory_write(context: …)` landed in `scope=custom`, which search read only when the caller passed the same label back — and `memory_stats` omitted custom contexts, so the label could not be discovered; measured live, such an entry was in the bank, in FTS and readable by `memory_get` while `memory_search` returned 0 results at every scope. No `contextLabel` now means every context in the project, one means that context only, project isolation unchanged |
| [0046 — "Rows belonging to this project" has one definition](0046-project-membership-has-one-definition.md) | `scope = 'project'` was hand-copied into nine queries, a trigger and a filter — six of them naming another copy as the authority — so ADR-0045 fixed search and stats while `memory_set_ttl` and `memory_share` still answered `unknown-hash` for an entry `memory_get` returned. The rule moves to `ProjectRows`, a gate compares the copies, and the TTL tie-break keeps its preference without using an existence filter to express it |
